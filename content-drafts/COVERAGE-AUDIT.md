- **扩容目标据此修正：2000 − 1156 = 新增 844 条**（下文全部配额以 844 为总数，逐格加总可复核）。

**计数口径（下文通用）**：

- 年龄段：22–34 / 35–49 / 50–64 / 65–80 四段。事件年龄窗 [min, max] 与年龄段有交集即计入该段（窗口重叠口径，与 PM-CONTENT 一致）。一名玩家一局只走一个年代，所以另给「玩家视角供给」表。
- 年代分类：事件带 `era` 字段 → 该年代专属；带 `eraIn` → 按名单共享（全库仅 5 条，均为 pack14 的智能机时代晚年条目，eraIn:[c1978, c2000]）；两者皆无 → 通用。

- 职业匹配口径：对 OCCUPATIONS 第二部分每行取职业名（及同义词表，见 §1.5），在可检索文本中命中 ≥1 条事件记为「已用」。命中数只说明文本在场，不说明该职业被写成了主角弧线——故已用再分两层：命中 ≥5 条为「成规模在场」，1–2 条为「一瞥」。

**薄格清单（按严重度排序）**：

1. **c1965 × 65–80 专属 = 0、c1978 × 65–80 专属 = 0**——已知薄格复核：**原样未补，两格仍是 0**（纯 era 口径）。c1978 靠 5 条 eraIn 共享条目在玩家视角下有 5 条「带年代限定的晚年事件」，c1965 连这 5 条都没有。
2. **c2000 专属 = 0（全年龄段）**。c2000 玩家的池 = 通用池 + 5 条 eraIn，没有一条为这一代人单独写的事件；「现代局无专属包、通用池即其年代」是当初的设计，但结果是 c2000 在 pickEvent 里永远吃不到 era 命中 ×3 权重，年代质感全靠通用池的现代物件词。
3. **65–80 段整体见底**：全池只有 pack14（75 条窗口达 65+）+ era1955（12 条）在供这一段，其余 15 个数据文件对 65–80 的贡献为 **0**。单岁密度：45 岁时窗内事件 522 条，75 岁只剩 47 条，80 岁只剩 17 条。65 岁以后**新进入**（min ≥ 65）的事件只有 21 条，其中 pack14 占 15 条——长局后 16 年基本是 pack14 一个包的独角戏，且它的 80 条里 65 条是 min 在 60–64 的「带入」事件。
4. **50–64 段专属偏薄**：c1955 专属 15、c1965 专属 17（PM-CONTENT 旧口径下这两格是 12/13，换到本审计年龄段后略高，仍属薄格）；c1978 专属 18 + eraIn 5。
5. **22–34 段专属不均**：c1978 专属只有 19 条，是四个年代包同段最低（c1955 为 30）——1978 年生 22 岁在 2000 年，互联网入场、非典、房价起飞全在这一段，专属供给却最少（浪潮组的伏笔也埋在这一段，见 §1.6）。
6. 全无条件保底事件（不带 route/era/require/forbid/all/any/chain/when/stats 中任何一个）共 529 条，分段 254 / 390 / 306 / **52**——65–80 段连保底都只有 52 条，条件事件再筛一轮后，某些标记组合的晚年玩家会真实地连续抽到微文本平年。

## 四、写手简报统一件清单（每名写手的 brief 开头原样附上）

### 4.1 文案纪律（docs/COPY-AND-AI.md 要点）

1. **说具体的事，不说抽象的理**：写「给家里换了台冰箱」，不写「感到无比充实」。情绪让玩家自己产生。
2. **句子长短像说话**：禁止排比三连、禁止金句收尾、禁止翻译腔（进行抉择/迎接挑战/开启新篇章）。
3. **数字像人记账**：写「账上只剩四个月工资」，不写「流动资金仅够维持 4 个月」。职业事件必须回到月工资、押金、计件单价这一层（OCCUPATIONS 使用说明）。
4. **禁词表（零命中才算交付）**：后来你才知道、才明白、原来这就是、不禁、油然而生、岁月、时光荏苒、人生就是、江湖。
5. **朗读测试**：每条读出声，像不像一个人在饭桌上讲另一个人的人生？不像就改。
6. **留白**：平平无奇的年份就平平无奇地过，不是每个事件都要点题。
7. **称呼与性别**：伴侣只称「对方/另一半」；玩家的孩子不写性别；他人孩子非必要不写。
8. **红线**：不涉政（无官职晋升线、党派、选举、军队；年代事件只写个人生活切面、不评价政策、无领导人姓名）；不玄幻（无超能力/预知/鬼神/风水；「神药」只指真实新药研发获批；彩票与加密暴富只许如实极低概率且写归于平静）；敏感题材写事不写惨、一个具体细节带过；不贬低任何一种活法，稀有不等于高贵。

### 4.2 六维格式与数值纪律

- 维度键只许六个：**health（健康）/ money（金钱）/ growth（成长）/ freedom（自由）/ relation（关系）/ wisdom（智慧）**。此外任何键名（包括把 freedom 写成 free、wisdom 写成 wise 之类）都是错字，会导致效果静默丢失、交付验收直接打回。
- 划界：**成长 = 本事**（技能、证书、职业资本，学与练得来，会被时代贬值）；**智慧 = 判断**（阅历与吃亏换来，只涨不贬）。考试晋升归成长，被骗/挫折/照护/读书/远行/带人/回望归智慧。
- 幅度：单项 −10..+10、单事件合计绝对值 ≤14（沿 PM-CONTENT 写手格式）。**智慧单次产出以 +2..+5 为常态**（存量均值 +4.35 是校准过的上限感，不是模板；照着抄会把智慧登顶率顶穿，见 §1.4）。**新事件不写负智慧**（存量负位点为 0，保持之）。
- **坏事默认带智慧补偿**：带负效果的选项/事件，除非叙事上纯属天降横祸，一般应同时给 wisdom +2..+5——「这一跤没白摔」要落在数字上（存量只有 29.9% 的负事件带补偿，新写口径提到默认带）。
- 选择比例：带 choice 的事件约 1/3（存量 31.7%）；有 choice 时效果只写在选项里。
- 保底纪律：每个包在每个 5 岁段至少 3 条**只带 era（或全无条件）、不带其他条件**的保底事件；晚年包尤其不许把条目全押在 has_kid 等条件上（无孩玩家要有完整的晚年）。

### 4.3 标记纪律（本项目踩过两次的坑，逐字执行）

**事故史**：v0.5 时 pack13/14 引用了 craft_hands、frugal、mentor 等从未被 set 过的标记名，约 60 条回响事件永久不可达，靠集成阶段映射抢救；§1.7 又确诊 route 自创名 4 条、顶层 set 死旗 12 个/连带 14 条。本节三条纪律就是对这三次事故的回应。

1. **setter 清单必须从代码实际抽取，不许凭记忆或仿照命名**。抽取方法（派单时由集成方执行一次并把结果附在 brief 后）：
   - 按 index.html 的加载顺序把全部数据文件（events.js、全部 packs、synergy.js）载入一个上下文，拼出完整事件池（含 combos；rare 单独列）；
   - 遍历全池每个事件及其每个 choice，收集**有效位置**的 set 值：`choices[].set`（事件/危机/稀有通用）、分岔 `forks[].choices[].set`、稀有事件顶层 `set`（仅稀有有效，见第 2 条）；
   - 同时遍历 `require / forbid / all / any` 的全部引用值，做差集：**被引用但不在 setter 集合里的名字 = 悬空引用，交付前必须为 0**；
   - 本审计实测基线（2026-10-31）：名义 setter 134、**有效 setter 122**（差额 12 即 §1.7 死旗）、被引用标记 81、有效口径悬空旗 8 个（死旗被引用所致，v0.9.2 修复中）。写手拿到的清单以派单时现抽的有效口径为准，本段数字只作对账锚点。
2. **立旗位置口径（据 §1.7 确诊）**：新事件给玩家立旗，**一律写在选项的 `choices[].set` 里**——这是已验证生效的位置。**普通事件顶层 `set` 禁止使用**（引擎从不应用，写了等于没写；稀有事件顶层 set 有效，但新写手不写稀有事件，不受此例）。
   - 待填（以 v0.9.2 修复轮结论为准）：v0.9.2 对存量 12 处顶层 set 的处置结论为 ＿＿＿＿＿＿（修引擎应用 / 数据迁移至选项，二选一，结论落地后由集成方回填本行；回填前一律按上一条的禁用口径执行）。
3. **引用纪律**：`require/forbid/all/any` 引用的标记只能来自抽取清单；**优先消费 §1.7 登记的 46 个已埋未用标记**（回响燃料现成，不要再造新标记）。确需新标记时：只能由本包事件的选项 set 定义、只能被本包事件引用，且必须在交付回报里逐个登记（名称 + 由哪条事件设置）。`chain` 只能填**已存在的事件 id**（核心 e_*、各 pack 已有 id、本包内 id），不能填标记名。`route/era` 只能用值域内的值：route ∈ {corp, home, abroad, study, gap}，era ∈ {c1955, c1965, c1978, c2000}——**自创任何路线名/年代名（stay、bigcity 类）视为未交付**。

### 4.4 交付格式

- 文件内容为 `window.GAME_PACKS = (window.GAME_PACKS || []).concat([ ... ]);` 纯数据，转换与并入由集成方负责。
- 字段：`id`（本包前缀+三位序号）、`min`/`max`（年龄窗）、`text`（正文 60–110 字）、`effects`（无选择事件的效果）、`choices`（最多一处：`{label, effects, echo, set?}`，echo 必填——存量 736 个事件选项 echo 缺失为 0，不许破例）、条件字段 `era/eraIn/route/routeIn/forbidRoute/require/forbid/all/any/when/chain/stats`。
- 职业条目用法（OCCUPATIONS 使用说明）：弧线要点是拆事件的骨架不是事件本身，每条职业至少拆出入行/上升/冲击/转行或晚年四拍中的两拍；拐点年份只作时间锚，事件从普通人节点里长。
- 交付回报必须含：条数、逐格（年代×年龄段）分布、新标记登记表、主主题分布——与 §二 配额对不上账的交付视为未完成。
