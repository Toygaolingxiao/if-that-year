# v0.13 机制轮设计稿：开局抽牌 + 「活过的人生」

> 状态：设计稿（只设计、不施工）。依据：用户 2026-10-31 两条裁定——①开局抽牌有必要（人生须随机开局、五条固定路线覆盖不了所有人）；②不做收集图鉴，改做「活过的人生」（口径：你活过的，是 N 种人生里的一种；记活过哪几种，不排高下、无完成奖励）。轻局模式已砍，不在本稿范围。
> 现状基线（v0.12.0，DEVLOG 定版与 STATE-MATRIX）：可抽池 2068（普通/组合）+ 稀有 28 + 特殊结局 17；死亡分布 早夭 3.68% / 60–79 岁 6.58% / 活到 80 岁 89.74%；判词登顶 关系 71.29%、垫底 金钱 90.54%；任一特殊结局 11.63%；实事件 44.19/局（普通口径）；智慧中位 46→60→78、打满 3.51%。
> 本稿与设计书 §2「不做随机出身/抽卡开局」一条的关系：该条立项时成立的前提是「出身全随机、玩家无选择」。用户本次裁定改变的是前提，不是推翻题眼——本稿的设计约束（§A2.4）就是把抽牌锁在「运气发牌、玩家选牌、路线仍是脊柱」的形状里，使它不滑向设计书否掉的投胎抽卡。施工落地时，设计书 §2 该条应同步改注为「已被 v0.13 裁定修订，边界见 DESIGN-V013 §A2.4」，不许两处口径并存。

## A. 开局抽牌

### A1. 牌面结构

**A1.1 类别：沿用三类，但「时代」改定义。**

外部简报的三类（家底 / 性格 / 时代）里，前两类成立，第三类与现行系统直接打架：年代已由玩家在设置区自选（c1955/c1965/c1978/c2000 四档，22 岁年份分别是 1977/1987/2000/2022），若「时代牌」再抽一次年代，等于把玩家刚选的东西没收重抽。改法：第三类保留「时代」之名、换其内容——**抽的不是哪一代，而是你这一代人里、落在你头上的那件具体的事**（下称「时代注脚」）。牌池按年代分池，每代 6 张，只从玩家已选年代的池里发。例：c1965 池里有「你上小学那年，学校停过一阵课」式的集体经历落点；c2000 池里有「你念初中时，学校后门有一排网吧」式的。判据与 v0.10 的年代专属口径一致：写不出「换个年代不成立」的，不许进时代池、归家底或性子。

三类定稿：

| 类别 | 管什么 | 叙事时点 |
|---|---|---|
| 家底 | 家里什么样：经济、父母职业、兄弟姐妹、住处 | 出生到成年，家里的账 |
| 性子 | 你是个什么样的孩子：体质、脾气、念书的路数 | 成长中形成的、带得走的东西 |
| 时代注脚 | 你这一代的具体落点：那件大事落到你家门上的样子 | 与所选年代绑定，按年代分池 |

**A1.2 抽选方式：每类发 3 选 1，共九抽三选。**

简报的「十抽三选」落到三类结构上就是每类三选一：发牌 9 张（3 类 × 3），玩家每类点选 1 张，手里留 3 张出身牌。发牌由种子决定（§A3），选牌是玩家动作——与全游戏的既有分工同构：种子管运气（事件池、影子变体），选择管人生（路线、8 个分岔）。牌面是运气，选哪张是态度；同一局链接的两个人看到同样的 9 张，选出不同的 3 张，这正是同局讨论的新话题（§A2.3）。

**A1.3 总牌数：48 张（家底 16 + 性子 16 + 时代注脚 4 代 × 6 = 24，其中每局实际可达 16+16+6 = 38）。**

简报「至少 30 张」的量级合理，但要按可达口径数：时代池分代之后，玩家一局能见的牌是 38 张量级。低于这个数，每类三选一会频繁撞见同一批牌（16 张里抽 3，一局见到该类近两成，两局重合感会很强）。48 张的写作量约等于半个事件包（v0.10 一名写手一包 70 条），可承受。再往上（每类 24+）边际收益递减且稀释审核，不做。

**A1.4 一张牌由什么构成（配比定稿）。**

| 成分 | 占比 | 口径 |
|---|---|---|
| 文案（牌名 + 一至两句） | 全部 | §A5 语气标尺 |
| 初始数值修正 | 全部 | 每张必有，2–3 个维度；幅度按强度档（§A4）。这是牌的主体作用，不许有「纯文案牌」——选了没感觉等于没选 |
| 立旗钩子（里程碑旗） | 约 1/3 的牌 | 牌可立一个里程碑旗（如「小时候在柜台后写作业」→ 记账/算术类钩子旗），供下游事件 `require` 消费。旗必须进注册表（名称 + setter = 该牌），走 v0.12 入库门。没有钩子的牌不许硬编旗 |
| 专属事件钩子 | 与立旗牌配套，v0.13 配套新写 12–18 条 | 钩子事件以钩子旗为 `require`（自带 ×3 权重，与现行 pickEvent 规则一致），分布在 23–45 岁（出身的回响应该来得早）。没有配套事件的钩子旗不许先立——v0.9.2 的教训是立旗漏应用/悬空旗，顺序必须是事件与旗同批入库 |
| 状态初值（setState） | **不用** | 六个状态域的初值由引擎与分岔叙事拥有（配偶 none、子女 undecided、双亲 alive、宠物 none）。出身牌若预设状态，等于在 22 岁之前就把 31/38 岁分岔或宠物线的入口改掉，叙事链会断。此口不开 |
| 事件权重的一般性修正 | **不用（本轮）** | 现行权重只有三条通道：require/state 门控 ×3、era 匹配 ×3、事件自带 `w`。给牌开第四条通道（按主题标签加权）需要先给 2000 条事件补标签字段，是另一个工程。本轮牌对事件池的影响只走钩子旗通道（门控 + ×3），如实写明，不假装有 |

### A2. 与现行系统的关系

**A2.1 两层分工：牌管出身层，路线管 22 岁去向。**

现行开局只有一层：STAT_META 初值（健康 60 / 金钱 45 / 成长 50 / 自由 50 / 关系 50 / 智慧 40）全员相同，路线 stats（corp 金钱+8/成长+10/自由−4/健康−4 等，单项 ±2..12）是唯一的开局差异。v0.13 后开局差异变两层：

- **出身层（牌）**：0–22 岁，你没得选的那些——以「发牌给运气、选牌给玩家」的折中形态出现。作用面：初始数值小幅修正 + 少量钩子旗。
- **去向层（路线）**：22 岁站在宿舍门口的那一选，五条路线原样不动，包括路线 stats、未选路线成影子的机制。

叠加顺序（引擎）：初值 → 牌面修正（applyEffects 一次结算）→ 路线 stats（现行顺序不变）。开局流水账在现行「22 岁 · 出发：{路线}」之前加一行出身行，把三张牌名如实记下（如「出身：家里开小卖部 · 打小坐不住 · 网吧那几年」），让牌在本局记录里有据可查——结算回望时玩家能看见这一局的起点是什么。

**A2.2 年代选择与时代注脚牌不打架的分工。**

玩家选年代 = 选世代（规则层：出生年、事件池的 era 门控与 ×3 权重、公历门换算，全部照旧）；时代注脚牌 = 世代内的个体落点（叙事层：只从所选年代的 6 张池里发 3 选 1）。换年代时只重发时代行，家底行与性子行不动（发牌派生方式见 §A3，这一条靠派生公式保证，不是界面补丁）。

**A2.3 影子人生只跟路线层走，牌层不设影子。**

现行影子是查表数据：每条未选路线有 4 阶段变体 + 3 条代价，瞥视在 30/40/50 岁（GLIMPSE_AGES），主影子 = 未选路线中的第一条。这套东西一寸不动。牌层不设影子的理由有三，都写明：

1. 出身不是「路」。影子的题眼是「没选的那条路」，预设了选择在先；出身牌是发到手里的，没选中的两张不是「另一条人生」，只是同一手牌的另外两张。把它们做成影子，题眼就从「选择」滑到「投胎」，正是 §2 否掉的形态。
2. 数据不存在。影子要成立需要每张牌一条平行人生线（阶段文案 + 代价），48 张牌 = 48 条影子线，内容量翻倍且质量必然稀释；路线影子是 5 条线养了六个版本的资产，不可比。
3. 牌层的对照功能由同局讨论承担：同种子的人发到同样的 9 张牌、选了不同的 3 张，「你为什么选那张」就是牌层的对照，不需要系统再演一遍。

结论：没选的牌不算影子的一部分；瞥视、影子代价、结算对照行（shadowCompareLines）全部只认路线。

**A2.4 防滑护栏（本设计不滑向投胎抽卡的四条锁）。**

1. **无稀有度**：牌没有等级、没有金银铜、没有「稀有牌」。视觉同权，文案不写吉凶（§A5）。
2. **不重抽**：不设重抽按钮（§A6.3）。运气不好就是这局的运气，与死亡、坏年份同一哲学。
3. **强度封顶**：牌面总影响不超过路线层（§A4 定档），出身决定不了人生走向，分岔与事件仍是主因。
4. **路线不动**：五条路线仍是玩家全权自选、无随机成分；游戏对外说法仍是「选一条路」，牌只是让每个人的起点不再长得一模一样。

### A3. 种子与复现

**A3.1 发牌用独立派生流，主 RNG 一根毫毛都不动。**

现行 RNG 是单流 mulberry 变体：`RNG.a = seedFromString(seedStr)` 后，全局按游玩顺序消费（路线不耗、事件抽取/稀有/危机/死亡/判词变体都耗），且 `rngA` 随存档落盘。若发牌从主 RNG 抽，哪怕只抽 9 次，整局的事件序列都会平移——所有旧同局链接（v0.12 及以前分享出去的）复现的将是完全不同的一生，这是不可接受的静默破坏。

方案：发牌 RNG 独立派生，与主 RNG 并行：

```
cardSeed 家底 = seedFromString(seedStr + "::cards::family")
cardSeed 性子 = seedFromString(seedStr + "::cards::temper")
cardSeed 时代 = seedFromString(seedStr + "::cards::era::" + eraId)
```

每类用自己的流做「池中抽 3 不重复」（消费次数固定为每类 3 次，与玩家选哪张无关——选牌是玩家动作、不耗任何 RNG，与分岔选项同理）。由此得到三个性质，施工验收逐条测：

- **主 RNG 序列零扰动**：发牌前后 `RNG.a` 不变（断言测试）；同种子、同路线、同选项的一局，事件序列与 v0.12 逐年一致——仅因初始数值被牌面修正，数值门控（stats/when/死亡线读健康）的判定输入变了，下游分岔是数值引起的、不是序列错位引起的。这与任何一次数值平衡调整的性质相同，同局链接的话术（同样的运气、不同的选择）仍然成立。
- **同局链接零改动**：现行链接只有 `?seed=&era=` 两参数（sameSeedUrl），不需要加牌参数——牌面由 seed+era 完全决定，对方打开链接、选好年代，看到的就是同一手 9 张牌。
- **分行独立**：换年代只重发时代行（家底/性子的派生不含 eraId）；改种子三行全换。界面不需要为「防串行」做任何补偿逻辑。

**A3.2 随机开局（不填种子）的牌面。**

现行随机开局是在点路线时才生成种子字符串（`Math.random()*1e6`）。抽牌要在选路之前发，所以候选种子的生成时点必须提前到开局页渲染时：页面打开即生成一个候选随机种子并据此发牌（种子输入框为空时显示的是这一手）；玩家在种子框输入并点「用这个种子」→ 按新种子重发三行；点「今日种子」同理。玩家什么都不管、直接选路 → 就用候选种子开局（与现行「点路线才 roll 种子」的结果等价，只是时点提前，玩家因此能在开局前看见自己的出身——这是抽牌玩法的必要前置，不是行为变更）。刷新页面 = 新候选种子 = 新一手牌（§A6.3 重抽口径与此挂钩，界面不另设按钮、也不必向玩家解释刷新这件事）。

**A3.3 存档。**

`S` 新增 `cards: [家底牌id, 性子牌id, 时代牌id]`（选定顺序固定为类别序），随现行存档（ify-save-v2）一起落盘，不升存档版本键。旧存档（v0.12 及以前）没有 cards 字段：续玩时按「无牌局」处理——不补发、不追溯改数值（数值早已是既成事实），cards 记空、出身行不出，无牌局与有牌局在结算页的唯一差别就是少一行出身行。回滚兼容：v0.13 的存档被旧版本页面打开时，cards 是未知字段、会被忽略（现行 loadSave 只读已知字段 + state 推导），不阻塞。

### A4. 强度档位（待用户裁定 —— 粗模拟实测）

> 占位牌组：按 §A1 的结构与 §A5 的配比临时造 36 张牌（每类 12、好 3 / 中 6 / 坏 3、效果签名与定稿口径一致），三档由同一牌组按倍率缩放：弱档 ×0.5（四舍五入）、中档 ×1.0、强档 ×1.6（单项封顶 ±8）。模拟为同构 headless 复刻 v0.12.0 引擎（met 含状态门/公历门、权重规则、死亡 v2、判词并列 rng 打破），策略口径与历轮一致（路线均匀随机、选项均匀随机、每类从所发 3 张中均匀选 1），每档 4 年代 × 4000 局 = 16000 局。先复现基线校验复刻保真，再读扰动。数字是设计估算，不是施工验收数（施工轮须以定稿牌组重跑）。

三档的幅度定义（每张牌 / 三张合计）：

| 档 | 单项幅度 | 每张牌修正总量（绝对值和） | 三张合计到某一维度的典型偏移 | 对照物 |
|---|---|---|---|---|
| 弱 | ≤±3 | ≤5 | ≤±5 | 路线单项最小步（±2）的两倍多一点，近乎香味 |
| 中 | ≤±5 | ≤9 | ≤±9 | 约等于一条路线的单项主修正（corp 成长 +10、gap 自由 +12）的一大半 |
| 强 | ≤±8 | ≤14 | ≤±15（同向叠满时） | 超过任何单条路线的单项修正——出身能压过去向 |

复刻保真（先行校验）：复刻基线对 v0.12 定版基线——实事件 44.29 对 44.19、关系登顶 71.38% 对 71.29%、特殊结局 11.45% 对 11.63%、智慧打满 3.79% 对 3.51%、死亡三项 3.49/6.33/90.19 对 3.68/6.58/89.74（偏差 ≤0.45pp）。全部指标偏差 ≤0.45pp，保真成立；扰动读数取「同复刻、同种子集」的档间差值。

数字来源纪律（本表专属，全轮适用）：本轮后台结果的系统转述曾两度给出与原始输出不符的数字，已全部弃用；下表每个数字均取自进程原始日志或落盘文件并经复跑核对——基线同种子跑三遍逐字一致、弱档跑两遍逐字一致，复刻的确定性已实证。

实测（每档 16000 局，括号内为对复刻基线的差）：

| 指标 | 复刻基线 | 弱档 | 中档 | 强档 |
|---|---|---|---|---|
| 早夭 <60 | 3.49% | 3.44%（−0.05pp） | 3.41%（−0.08pp） | 3.45%（−0.04pp） |
| 死亡 60–79 | 6.33% | 6.24%（−0.09pp） | 6.04%（−0.29pp） | 6.21%（−0.12pp） |
| 活到 80 | 90.19% | 90.32%（+0.13pp） | 90.55%（+0.36pp） | 90.34%（+0.15pp） |
| 判词登顶 · 关系 | 71.38% | 70.91%（−0.47pp） | 69.56%（−1.82pp） | 67.42%（−3.96pp） |
| 判词登顶 · 智慧 | 10.24% | 11.04%（+0.80pp） | 12.32%（+2.08pp） | 14.83%（+4.59pp） |
| 判词垫底 · 金钱 | 91.07% | 91.48%（+0.41pp） | 91.44%（+0.37pp） | 91.42%（+0.35pp） |

读数（四条）：

1. **死亡分布三档都动不了**（所有差 ≤0.36pp，噪声量级）。原因在模型里：死亡线是年龄主导的 Gompertz 曲线，开局 ±几点的健康差被 58 年的事件漂移洗掉。任何档位都不危及 MORTALITY-MODEL 的校准，这一项不构成选档约束。
2. **特殊结局三档都在涨，涨幅由牌组的净注入决定**：弱 +1.39pp、中 +1.48pp、强 +3.04pp。机理：占位牌组的期望净注入为正（好牌净 +3..+5、中性牌 +1..+3、坏牌约 −1，每张期望约 +1.5），特殊结局多以数值阈值（stats gt）为门，正注入把临界局成批推过门槛。弱档与中档涨幅几乎相同不是巧合：弱档 ×0.5 的取整使 −1 归零、+1 保留，实际净注入远超中档的一半——弱档在这一项上并不比中档「弱」。按定版基线 11.63% 折算：弱/中档约 13.0–13.1%，正压在 10–13% 目标带的上沿；强档约 14.7%，明确越界，强档出局。推论比选档更重要：**牌组必须设净注入预算**——定稿牌组要把「三张牌的期望净注入」压到接近 0（好牌的正总量由坏牌与权衡牌对冲），这一项的涨幅大半可随之消掉；批 5 以「特殊结局 ≤13%（定版口径）」为真硬门，越线先压预算、再不行才降档。
3. **智慧是第二敏感项**：智慧登顶与打满随档位单调上升（打满：基线 3.79% → 弱 5.01% → 中 5.86% → 强 8.05%）。机理：智慧初值最低（40），开局注入的边际杠杆最大；且占位牌组按「坏事给智慧补偿」的签名规则写、智慧正注入偏密，同属牌组构成效应。结论：**牌组再设智慧预算**（建议：每类智慧为正的主注入牌 ≤3 张、单卡智慧 ≤+3、坏牌补偿智慧计入预算），施工模拟以「智慧打满 ≤4.5%（复刻口径）」为硬门。
4. **关系登顶随档位下降是附带收益**（弱 −0.47pp、中 −1.82pp、强 −3.96pp）：不是关系变弱（关系打满率不降反微升），是智慧等维度被抬起来参与竞争。它顺手缓解了挂账多轮的关系登顶问题，但量级不足以当平衡手段，平衡轮的账不因此销。金钱垫底三档同向微升 +0.35..+0.41pp，属注入抬高其他维度后的相对效应，不构成问题。

**推荐：中档（附两个预算与一条回退线）。** 先说清弱与中的真实差距：模拟扰动上两档几乎同级（特殊结局只差 0.09pp、死亡同为零扰动），中档只在智慧打满上更贵（+2.07 对 +1.22pp），在关系登顶上更有益（−1.82 对 −0.47pp）。选档因此主要由体感裁定：弱档单项 ≤±3、三张合计典型偏移 ≤±5，玩家选完牌到结算很难感到出身起过作用，违背 §A1.4「选了没感觉等于没选」；中档的单项 ±5 与路线主修正同量级的一半，选牌有实感又不压过去向（护栏 3）。强档出局理由不变：特殊结局 +3.04pp 越界、智慧打满翻倍、关系登顶 −3.96pp 说明出身开始替玩家决定判词形状。回退线写死：定稿牌组（带净注入预算 + 智慧预算）在批 5 模拟下若特殊结局仍越 13%，先继续压净注入预算；预算压尽仍越线，降到弱档重跑，不许靠改结局阈值掩盖。施工轮以定稿牌组重跑同口径模拟复核本表，数字以那一轮为准。

### A5. 牌面文案与红线

**A5.1 语气标尺（在 COPY-AND-AI 全文之上，牌面专属补三条）。**

1. **写事实，不写命。** 牌面只许写 22 岁之前已经发生的事（家里开过什么、你小时候什么样、那年出了什么事），不许写它「意味着」什么，更不许吉凶断言：禁「天生」「注定」「命里」「福气」「旺」「克」一类词进牌面（施工时加进校验词表，牌面文件单独扫）。
2. **出身有好有坏，但贵贱不写。** 坏牌写具体的难处（一笔账、一种病、一间屋子），不写家庭的「层次」「出身不好」这类标签；好牌写具体的便利（一门手艺、一个院子、一柜子书），不写「赢在起跑线」。玩家读完应该觉得「哦，是这么个起点」，而不是「这手牌赢了/输了」——这也是无稀有度的文案侧配套。
3. **自嘲落在自己身上。** 简报要的「一点自嘲」只许自嘲玩家角色的当年（如堵在网吧门口、柜台后写作业），不嘲父母、不嘲阶层、不嘲年代。幽默来自情境（COPY-AND-AI 第 3 条原话）。

**A5.2 好/中/坏的配比（呼应「不如意」口径）。**

每类牌池内：好牌（效果签名纯正）约 1/4、中性/权衡约 1/2、坏牌（净负）约 1/4。坏牌不得是纯粹的惩罚：每张坏牌带一个小额补偿（以智慧为主，与 v0.9.0 的签名规则「坏事给智慧补偿」同源），但净签名必须为负——补偿是「这一跤没白摔」，不是把坏牌洗成好牌。发牌不做保底：一手三张同类全坏（概率约 1.6%）是允许的，手气本身就是同局话题的一部分；且坏的只是起点数值，分岔与事件池不受牌面封顶影响（护栏 3）。

### A6. 界面

**A6.1 位置与屏数：零新屏。**

抽牌长在现行开局页里，不新增页面、不新增步骤。现行开局页结构是：标题与引言 → 路线五选 → 续玩 ghost → 设置块（年代/自动推进/速度 + 一行摘要）→ 种子行。v0.13 的插入法：

- 牌面区放在引言与路线之间——阅读顺序是「你是谁（出身）→ 你去哪（路线）」，与叙事顺序一致。
- 牌面区三行：每行一个类别小标（家底 / 性子 / 时代，只给名称，守 COPY-AND-AI 第 8 条「设置与选项不写说明词」）+ 三张牌横排（窄屏改纵列，见 A6.2）。
- 每行预选所发的第一张（高亮态与现行 segbtn 的 .sel 同形制），玩家可改选；选路按钮永不因牌未选而禁用（预选保证任何时刻都有完整的三张牌），「选路即开局」（§15 已定）一字不改。
- 年代 segbtn 改选时只重发时代行（§A3.1 的派生保证）；种子「用这个种子」/「今日种子」重发三行。重发时已选位置重置为第一张（新牌面无所谓「保留选择」，保留的是类别位置而非具体牌，重置并高亮即可，不弹窗、不提示——设置区不写说明词的口径下，变化本身就是反馈）。
- 摘要行（setsummary）加牌面一项：现行格式「这一局：{年代} · {出生+22} 年 22 岁 · {种子} · {自动推进}」，改为在种子项后加「· 出身 {牌名}/{牌名}/{牌名}」——仍是一行事实回显，无说明词。

**A6.2 牌面形态与窄屏。**

一张牌 = 牌名（粗）+ 文案（正文小字）+ 数值行（「金钱 +3 · 成长 +2」，事实数字，允许）。宽屏一行三张并排；窄屏（<640px）每类的三张改纵向堆叠、整行可点、命中高度 ≥44px（与 v0.8.0 的命中区标准一致）。不做翻牌动画、不做抽牌特效：`prefers-reduced-motion` 全局规则已在，牌面出现方式与设置块一致（静态呈现 + 选中态描边），仪式感来自「这是你的出身」这件事本身，不来自动效。

**A6.3 重抽：不设按钮，口径写死。**

重抽与种子复现的矛盾是结构性的：若允许「只换牌、不换种子」，则同一种子对应多手牌面，同局链接立即失效；若重抽 = 换种子，则它已经存在——刷新页面即新候选种子、开局前改种子即新手牌面。所以：不设重抽按钮、不写重抽文案；玩家想要另一手出身，路径是换一个种子（与「想要另一局运气，换种子」是同一件事，概念不新增）。这一条要在施工 DEVLOG 里明示为裁定而非遗漏。

## B. 「活过的人生」（本地记录，不是图鉴）

### B1. 数据：记什么、不记什么

存储：localStorage 新键 `ify-lives-v1`，结构 `{ v: 1, endings: { <end_id>: "YYYY-MM-DD" }, rares: { <r_id>: "YYYY-MM-DD" } }`——只存「哪一种 + 第一次活到的本地日期」。全部本地、无上传、无账号，与项目隐私最小化口径（localStorage only）一致；记录页脚注一行如实说明「存在这台设备的浏览器里，清掉浏览器数据就没了」。

| 候选记录项 | 记否 | 理由 |
|---|---|---|
| 特殊结局 id（17） | **记** | 有标题、是「一种人生」最完整的单位；结算时 `specialEnding()` 已算出，落盘只是一次写 |
| 稀有事件 id（28） | **记** | 稀有际遇是玩家真实的谈资（「我撞上过彩票那条」）；`usedRare` 本局已有，结算时并入即可 |
| 判词 top/bottom 组合 | **不记** | 判词是数值形状的收尾文（1080 种组合），记它等于把记录页变成 1080 格的收集表——正是用户否掉的形态；且判词同种子可复现、不构成「活过」的稀缺事实。记录的单位是「人生与际遇」，不是「文案排列」 |
| 普通事件 id | 不记 | 2000+ 条、无标题、记了也无法呈现；流水账已在本局内承担记录功能 |
| 活过次数 | **不存** | 只存首次日期。次数会诱导为凑数重刷同一路线，与「记活过哪几种」的口径相悖；存了不用更怪，所以从源头上不存 |

**呈现侧的前置数据缺口**：稀有事件在数据里没有标题（只有 text），记录页需要一个短标签。v0.13 内容批给 28 条稀有各补一个 `label` 字段（如 r_lottery → 「楼下中了头奖」），账本体、只作记录页与线索的锚，不改 text、不改任何门控。特殊结局已有 title，无此问题。

**跨版本 id 变更的处理**：id 是字符串主键，历轮只增不改名（v0.10→v0.12 均是）。规则定为：呈现时以当前版本数据为准——记录里有、当前数据里没有的 id（孤儿 id）不显示、也不计入已活数，但**不从存储里删**（防版本回滚或 id 复用时记录凭空消失）；未来版本新增结局/稀有，总数 N 随版本变大，已活记录不受影响。N 的口径因此是「当前版本一共有多少种」，记录页文案按此写（§B2），不假装 N 是宇宙常数。

### B2. 呈现

**B2.1 入口两处，都克制。**

1. **结算页一行**（本局有新纪录时才出）：判词与标签行之后、影子对照之前，一行小字——新结局：「这种人生，你第一次活到。」；只有新稀有：「这件稀罕事，你这回头一次撞上。」；两者都有时只出结局那行（稀有不抢）。本局无新纪录时整行不出——沉默是常态，不许每局都提醒玩家「你还差 X 种」（那是收集话术）。
2. **记录页**：开局页设置块下方加一个 ghost 入口「活过的人生」（与续玩 ghost 同级、无红点、无计数徽标）；点开是站内一个视图（与结算页同构的单页渲染），结构：
   - 页眉一句：「你活过的人生」+ 一行总述：「结局活过 {X} 种，稀有际遇撞过 {Y} 件。每一种，都只是众多人生里的一种。」（X/Y 是事实计数，不是完成度——不带分母百分比，见禁止项。）

   - 「稀有际遇」组：同构，活过的出 label + 日期，未撞过

   - 页脚一行：存储口径（§B1 的本地说明）+ 一个「清空记录」文字按钮（清的是 ify-lives-v1，不碰存档与偏好；点了要二次确认——这是玩家的人生记录，不是缓存）。

**B2.2 未见条目的线索写法（样本 3 条）。**

线索只许做一件事：让玩家知道「还有这样一种人生」，但不知道它叫什么、怎么触发、离自己多远。写法守则：写那种人生的一个具体侧面（账本体，与事件文案同语感）；不写触发条件（「需要先立某旗」是攻略，不是线索）；不写任何稀缺程度的话（「很少有人」「没几个人见过」是无数据的断言，且是收集话术）；不写玩家群体的话（「听说有人……」把记录页写成传闻墙，错位）。

- end_richest（世界首富）未见线索：「把副业干成大公司，最后站在锣声里的人。」
- end_village_doc（村医一辈子）未见线索：「在乡镇卫生院的门诊椅子上，坐了一辈子的人。」
- r_lottery（稀有 · 中头奖）未见线索：「楼下彩票站贴出红纸那天，名字没写、照常去上班的人。」

**B2.3 总数 N 的口径（待用户裁定，给出说法）。**

用户的原话是「你活过的，是 N 种人生里的一种」。N 有三种取法：

| 取法 | N | 说法 |
|---|---|---|
| 只算结局 | 17 | 「人生」的单位最纯：一种结局 = 一种人生走法。但稀有际遇（28 件）会被排除在总述之外，与它们同页呈现时口径打架 |
| 结局 + 稀有合计 | 45 | 数字有分量、与记录页内容一致；但把「一件事」和「一种人生」混成一个单位，严格说不准 |
| 分开报（本稿推荐） | 不设单一 N | 总述句分开报两个事实数（§B2.1 的句式），「众多人生里的一种」作收尾的定性句、不挂具体总数。理由：用户的口径精髓是「每一种都只是其中之一、不分高下」，不是要一个分母；分开报既不混单位、也不用为了凑一个 N 牺牲准确性。若用户想要一句带总数的对外说法，再在 45 与 17 之间二选一 |

**B2.4 明文禁止项清单（施工验收逐项核对，出现任意一条即退回）。**

1. 完成度百分比（如「已活过 37%」）与任何形式的进度条；
2. 稀有度标记：星级、颜色分级、传说/史诗/稀有字样（tier 是 synergy 数据的内部字段，记录页与结算页都不许透出——现行结算页已守此界，记录页同守）；
3. 解锁/集齐文案：「解锁」「集齐」「还差 X 种就满了」类句子，以及未见条目的锁图标、剪影图；
4. 奖励：任何与记录挂钩的奖励、称号、特权；
5. 排序按稀有度：组内只许按数据原序或首次活过日期序；
6. 提醒机制：红点、徽标计数、开局页的「未完成」提示；
7. 社交比较：记录不进同局链接、不生成「我的图鉴」式分享图（§B3）。

### B3. 与分享的关系

**记录不进分享卡、不进发帖文案、不进同局链接。** 理由：分享卡的既定构成（判词 + 标签 + 影子 + 同局链接）卖的是「这一局」，记录是「我这个人玩过多少」——后者一旦上卡，卡的性质就从表态变成炫耀收集，与 §B2.4 同一条线。唯一允许的交叉：本局命中的特殊结局名本来就在结算页以标题形态出现（v0.11 既定分层），分享卡是否带结局名维持现行口径、本轮不改。记录页本身不设分享按钮。

## C. 顺带议题：再结伴载体事件（可选批，待用户点头）

**缺口现状**（STATE-MATRIX §4）：注册表已登记 divorced→partnered、widowed→partnered 两条 reserved 边，校验门只警告；存量候选 p27_006（止于一杯咖啡）、p28_006（正文是回绝）均不合格，v0.12 裁定「不硬造」。

**可行性：高，且是全轮成本最低的一批。** 引擎与注册表零改动——新事件写好后把 id 填进两条边的 `by`，校验门警告自动消除。需要的写作量：每条线 2–3 条，共 4–6 条，结构为「相识 → 相处 → 结伴落点」：

| 线 | 条数 | 结构与门控 | 落点 |
|---|---|---|---|
| 离异线（pack31 暂名） | 3 | ①相识（state.spouse=divorced，38–56 岁）选项立里程碑旗（如 re_start）；②相处（require 该旗，chain 指向①）；③落点（require 该旗）选项级 setState spouse→partnered | 完整走完才流转；中途「算了」选项真实存在且不惩罚 |
| 丧偶线 | 2–3 | 同构，年龄窗后移（50–70 岁）；节奏更慢：先写「把日子重新过起来」的具体事（收拾屋子、恢复晨练），相识不许紧贴丧偶事件年份（min 与 p28_001 的年龄窗拉开） | 同上，setState spouse→widowed 的反向边即 widowed→partnered（reserved 已登记） |

**文案口径**：写事不写惨——不写「走出阴影」，写一起买菜、对方记不住你忌口又慢慢记住这类具体相处；过「不如意」口径——4–6 条里至少 1 条持平收尾（处了一阵，觉得还是一个人自在，散了，关系没变仇人）、落点事件的效果签名必须是权衡（关系 +、自由 −），不许纯正面（再结伴不是「奖励结局」）；新伴侣的称呼守现行口径用「对方」，不与前段关系做比较句（「比上一个好」类句子禁写）。

**已知连带风险（如实登记，不在本批解决）**：流转回 partnered 后，全部 partnered 门控事件重新开放，其中少数事件在叙事上预设「对方是孩子的另一位家长」或「相伴多年」（如组合事件 cb_family3 的 stateAll spouse=partnered + kids=has）——再结伴玩家抽到时会有轻微错位。这是存量事件未区分「初婚伴侣/再结伴伴侣」的老问题（v0.11 ⑥ 登记的 partner_now 张力的另一面）；本批只立线、不动存量，错位面小（组合事件仅 8 条且各有其他门控），登记在案、留待内容轮按需给个别事件补 stateNot 或旗标区分。

**建议**：并入 v0.13 施工轮作独立可选批（批 4）——它与抽牌/记录无耦合，用户不点头就整批砍掉，不影响其余批次。
