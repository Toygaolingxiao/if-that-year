# 增长产品文档：首页克制、分享闭环、留存与指标（PM-GROWTH v1，2026-10-31）

> 视角：增长 PM。依据：`docs/DESIGN-BOOK.md`（§8 裂变、§8.6 裂变数学、§9 推广、§12 止损）、`docs/SCALING.md`（L2 才加后端四个小口子）、`docs/SYNERGY-AND-RARE-ENDINGS.md`（特殊结局实测 10.0%、组合可视化待办）。
> 首页形态的判断来自用户实测反馈：门户式堆叠（语言栏、巨号标题、实时计数、统计面板、众人 feed、悬浮开始键）「有点太乱」，本项目不走这条路。分享台的形态（感想进发帖文案开头、系统分享大按钮、卡型×尺寸矩阵、发帖文案预览）已按 §2 定版并落地。实时计数与统计面板不做：那需要真数据底座，我们没有，做了只会是假数与噪声。

---

## 0. 三条总原则（后面所有取舍的依据）

1. **落地页 = 开局页，一屏只干一件事：让玩家点一条路开始。** 我们的 pages.dev 没有门户的命：无后端、无账号、无内容库存。社会证明只许以「静态、精选、可核查」的形式出现，任何需要实时数据的模块（计数器、feed 流）一律不做——不是以后再说，是做了必乱、必假、必养不起审核。
2. **增长的主引擎不是首页，是结算后的分享台与同局链接。** 设计书 §8.6 已算清：广播分享在绝大多数情景下系数 <1。所以优先级排序是：分享闭环（P0）＞ 同局落地体验（P0）＞ 首页点缀（P1）。首页再热闹，也补不上分享率的缺口。
3. **每个数都要能被测到，才许上线对应功能。** 当前纯前端无埋点（SCALING L2 才有匿名埋点口子）。指标节（§4）列的事件埋点是 P0 前置：没有它，完局率之外的一切都是猜。

## 1. 首页（落地即开局页）：该不该加社会证明/内容区

### 1.1 结论

**加，但只加两块静态内容，且全部放在开局卡下方；开局卡本身一个字不让。** 不做门户口，不做 feed，不做实时元素。首页结构定版为三段：

```
[第一段 · 开局卡]  标题 + 一句话 + 5 条路线（选即开局） + 「这局的设定」折叠区
[第二段 · 今日种子条]  一行日期种子入口（见 §3）
[第三段 · 精选故事]  3 张静态精选卡 → 链到静态故事墙页（见 §3.3 的 MVP）
[页脚]  隐私口径一句话 + 数据与虚构说明入口（设计书 §5 L2 的信任卖点）
```

### 1.2 加什么（克制版清单）

| 模块 | 形态 | 优先级 | 验收口径 |
|---|---|---|---|
| 今日种子条 | 一行条幅：「今日种子 · {月}月{日}日——今天点开的人，同一道题」+ 一个「就玩今日种子」按钮，点了直接以今日种子进选路状态（种子已预填并锁定提示） | P1（今日种子按钮已在设定区，此为提级展示） | 条幅在开局卡之后、折叠区默认态下第二屏内可见；点击到开局 ≤2 步 |
| 精选故事 3 卡 | 编辑人工精选的 3 条真实玩家人生（经授权，见 §3.3 隐私口径），静态打包进站点，每张卡只有：判词一句 + 关键分岔一句 + 「TA 的种子」同局入口。随版本人工轮换，不自动更新 | P1 | 3 张卡全部有书面授权记录；每张带同局链接且可正常开局；无任何未经授权的反思原文 |
| 一行可核查的社会证明 | 放在页脚上方，二选一：①有真实数据时写「内测 {N} 人玩过 · 数据截至 {日期}」且 N 必须能从埋点/内测名单对上；②没有数据时只放一句经授权的玩家原话（带出处如「——内测玩家，玩了两局」）。**禁止**写「已有 XX 万人玩过」式无源数字，禁止虚拟实时计数 | P2 | 文案上线前逐条核对来源；数字与埋点后台抽查一致 |

### 1.3 明确不加什么（及原因）

| 不加 | 原因 |
|---|---|
| 实时出生/死亡式计数器 | 那是投胎题材的本体数据；我们若做「正在玩的人数」只能造假或接后端，且传达的是热闹不是好奇——与「看另一条路」的钩子无关 |
| 众人人生 feed 流 | 需要后端 + 投稿审核 + 隐私处理三件套（SCALING L2 阶段才有），且无限滚动 feed 正是「乱」的最大来源；用 §3.3 的静态精选替代 |
| 按国家/年份的统计面板 | 那需要大规模真实数据底座，一个人维护不起（设计书 §2 取舍已判）；我们的可信度靠「数据与虚构说明」页，不靠面板规模 |
| 语言切换栏 | 中文先行是已定路线（设计书 §1.3）；日文版立项后再加，且只加在页脚 |
| 悬浮开始按钮 | 开局就是本页唯一主任务，不需要悬浮件再抢一次注意力 |
| 主题包/珍藏的首页推销位 | 收费点后置到结算与珍藏页（设计书 §10：免费玩完整一局）；首页出现价格会把情绪产品降格成工具站 |

### 1.4 开局设置（年代 / 跨度 / 种子）如何收纳才不乱

现状风险：年代（4 档）× 跨度（5 档）× 种子（输入框+今日种子）+ 5 条路线全平铺，开局卡会变成表单页——这正是首页「乱」在我们这里的对应形态。本文当时的定版方案是**渐进披露，三层**（后被用户裁定取代，见文末状态更新）：

- **第 0 层（默认可见）**：只有标题、一句话、5 条路线。选路线 = 立即开局，用默认设定（2000 年生 · 走到 65 岁 · 随机种子）。验收：从落地到进入第一张事件卡 ≤1 次点击（不含选路本身即共 1 次）；移动端 390×844 首屏内完整看见 5 条路线，无横向滚动、无被遮挡。
- **第 1 层（折叠区「这局的设定」）**：一个折叠开关，折叠态只显示一行当前设定摘要，如「2000 年生 · 走到 65 岁 · 随机种子（点开可改）」。展开后才出现年代 4 选、跨度 5 选、种子输入，三组各占一行、组间留白，**不许**三组同时以按钮墙形态出现在默认态。验收：折叠默认关闭；展开后三组设置各 ≤1 行标题 + 1 行选项；改任一项后摘要行实时同步。
- **第 2 层（场景化预设，只露一个）**：唯一允许上浮到第 0 层的预设是今日种子（§1.2 条幅），因为它同时是留存仪式（§3）。同局链接进入的玩家走 §2.3 的挑战落地态，不经过普通开局页布局。

补充红线：设定项文案说人话，不说参数话——「替哪一代人重走一遍」优于「出生年代」，「这一局走到几岁」优于「跨度/终局年龄」（引擎现用语已是前者，保持）。

## 2. 分享台上线后的传播闭环

### 2.1 分享文案规范（定版，写进分享台的默认填充，不许临场发挥）

分享台已定形态：感想输入（进文案开头）→ 卡型（判词卡/流水账卡）× 尺寸（4:5 / 9:16）矩阵 → 发帖文案预览 → 系统分享主按钮 + 保存图片 + 复制文案三件套。文案规范补齐如下：

**默认发帖文案模板（玩家未填感想时）**：

```
我在《如果那年》活了一局：{判词一句}
{关键分岔一句，如「28 岁，我没回老家。」}
另一条路上的我：{影子一行}
同样的运气，你会怎么选？{同局链接}
```

**玩家填了感想时**：感想原样置于文案第一行（结构定版的理由：玩家的话是表态，不是广告词），其余结构不变，感想不进卡面大字区、只进文案与卡面小字区（防止卡面被不可控文本毁版）。

规范细则：
- 全文 ≤110 字（不含链接），适配各平台一屏读完；超出时先砍五维数字行，判词与影子行不许砍——那是钩子本体（设计书 §8.1 五要素）。
- 链接只放同局链接（带种子+年代+跨度，见 §2.3），不放裸首页链接：点进来的人要落进「同一道题」，不是落进门户。
- 禁止项：不写「击败了 X% 玩家」、不写分数排名、不写「快来测测你的人生」式测试腔、不预置 hashtag 超过 2 个（默认给 `#如果那年` 一个，其余让玩家自己加）。
- 验收：四种卡型×尺寸组合各导出一次，文案与预览逐字一致；感想为空/20 字/60 字三档下文案均不溢出、不重复拼接。

### 2.2 卡面钩子 A/B（各给具体文案，上线后按 §4 指标 3 判定）

卡面其他元素（判词、关键分岔、影子一行、五维形状）两版相同，只换底部钩子行与行动句：

- **A 版 · 同命对照型（主推）**
  钩子行：「同一种子，同一套运气。」
  行动句：「我选了这条。你来选另一条，看能走到哪。」
  逻辑：卖可比性（设计书 §8.3 共同题目感），点进来的人有明确任务——赢不赢不论，先想知道「换我会怎样」。
- **B 版 · 影子悬念型（挑战）**
  钩子行：「另一条路上的我，后来过得比我好吗？」
  行动句：「我有 {N} 次没敢看。链接在这，你敢看完吗？」（{N} 为本局真实跳过瞥视次数；N=0 时换行：「三次瞥视我全看了。链接在这，你呢？」）
  逻辑：卖未揭晓的影子线（设计书 §5 L1 的好奇缺口），用玩家本人的真实行为数据做钩子，每张卡天然不同。
- A/B 分配：按种子尾号奇偶固定分组（一人恒定一版，避免同人两版污染）；观测窗 2 周或每组 ≥300 次有效分享，先到为准；胜者保留、败者下线，不许两版长期并行稀释。判定指标用 §4 指标 3（每千名玩家有效分享卡数）与指标 4（同局链接开局率）双看：只涨分享不涨开局的，算输。

### 2.3 同局链接的落地体验：已有什么、还差什么

已实现（现状基线）：结算页可复制同局链接；朋友点开带种子参数、开局页有种子输入、可同一种子开局；今日种子已上线。

还差四件，按优先级：

| # | 缺口 | 方案 | 优先级 | 验收口径 |
|---|---|---|---|---|
| 1 | **链接只带种子，不带年代与跨度**——朋友用 2000 年生 65 岁局打开你 1955 年生 80 岁局的种子，根本不是同一道题，对照失效 | 链接参数补 `era` 与 `end`，落地时自动套用并在挑战横幅里明示 | P0 | 用一条 c1955/80 岁局生成的链接在新浏览器打开：年代、跨度与分享者一致，横幅文案正确显示 |
| 2 | **落地无挑战上下文**——朋友点开只是普通开局页，不知道「谁让我玩、他活成了什么样」，定向挑战的社交压力全丢了（设计书 §8.2 的核心资产） | 链接再带一个紧凑的挑战摘要参数（分享者判词一句 + 关键分岔一句，URL 编码，总长控制在 200 字内）；落地页顶部出一条挑战横幅：「有人用这套运气活了一局——{判词}。换你来。」+ 一个主按钮「用同一种子开始」。只带判词与分岔，不带五维数值细节（不剧透原则） | P0 | 横幅在落地页首屏可见；点主按钮 1 次直达选路且设定已锁定为链接参数；无参数的普通访问不出现横幅 |
| 3 | **朋友完局后没有自动对照**——Loop B/C 的第二张卡（对比卡）要靠手动，闭环在这里断掉 | 朋友以挑战链接完局时，结算页在判词区下方出一块「同局对照」：左分享者判词（来自链接摘要）、右本人判词，并提供「生成对照卡」入口（复用流水账卡版式即可，不新做卡型） | P1 | 挑战链接完局必出对照块；普通链接完局不出；对照卡可正常导出且两行判词无串局 |
| 4 | **链接太长、无 OG 预览图**——聊天软件里点开率吃亏 | 短链与动态 OG 属 SCALING L2 的后端小口子（短链服务），立项条件是先有埋点数据证明 Loop C 值得投入；在那之前只做一件事：OG 图用静态判词卡样图、OG 描述写死为「同一种子，同样的运气，不同的选择。」不假装个性化 | P2 | 短链立项评审时拿出指标 4 的 4 周数据；OG 静态版上线后各平台预览无缺图 |

## 3. 留存

### 3.1 今日种子做成每日仪式，还缺什么

今日种子只是「每天有一道公共题」，离「仪式」还差三件，全都可以先用**零后端**（localStorage）版本落地：

| 缺口 | 零后端方案（P1） | 验收口径 |
|---|---|---|
| 没有连续性 | 本地记录玩过今日种子的日期集合，开局页今日种子条下加一行小字：「这是你第 {N} 天玩今日种子。」只报累计天数与当前连续天数，**不做**断签惩罚、不做火焰/红色角标这类焦虑设计（与人文定位冲突）。文案口径诚实标注本机口径即可，不写「全网第 N 人」 | 同一设备连续两天各玩一次今日种子，第二天显示连续 2 天；清缓存后归零属预期行为，不处理 |
| 没有昨日回看 | 本地存最近一次今日种子局的结算摘要（日期、判词、是否特殊结局、种子）。次日开局页今日种子条下出第二行：「昨天的今日局，你的判词是『{判词}』。」点它可复制种子重开昨日局 | 昨日玩过今日局，今日打开必见回看行且判词逐字一致；昨日没玩则不显示（不许编造） |
| 没有明日期待 | 今日种子条尾加一行静态预告：「明日种子，0 点刷新。」仅此一句，不做倒计时组件（倒计时是电商语言，且静态页做不准跨时区口径） | 预告行与日期切换逻辑一致：本地 0 点后条幅日期与种子同步更新 |

明确不做：断签挽回弹窗、连续天数排行榜、每日签到奖励——这个产品卖的是回望，不是打卡；上述玩法与 §7 人文纪律冲突，且都需要后端。

升级路径（P2，需 SCALING L2 埋点后）：匿名聚合的「今日局判词墙」——只展示当日今日种子玩家判词的匿名聚合分布（如「今天 63% 的人判词落在关系维」），无个体内容、无 feed，放在今日种子条的落地小页，一周一更都行。这是把共同题目感做满的最后一步，但必须有真实数据才许上。

### 3.2 故事墙（UGC 人生墙）：最小版本

分两步，第一步甚至不需要投稿系统：

**第一步（P1）：静态精选墙。** 独立静态页 `/stories`（或站内一页），收录 ≤12 条经授权的真实分岔故事，来源是内测与首发期的定向征集（设计书 §6.4/§8.5 的故事征集），人工编辑成与游戏同构的格式：年龄 + 那年的分岔 + 选了什么 + 后来怎样的一行 + 对应的游戏种子入口（「用 TA 的分岔开一局」）。首页只放其中 3 张做入口（§1.2）。更新节奏随版本人工轮换，写明「每月更新」即可，不承诺频率。
验收：每条故事有授权记录编号可查；每条带可玩的种子入口且能开局；页面为纯静态，无评论区、无点赞数。

**第二步（P2）：投稿入口。** 等 SCALING L2 的投稿小口子（无服务器函数 + 托管库 + 审核后台）就绪后开，或先用外部表单过渡。投稿 → 人工审核 → 入选才进静态墙（审核后仍静态发布，不做实时 UGC 流）。永远不开：实时发布、评论、点赞排行、「烛光数」这类苦难计量。

### 3.3 故事墙隐私口径（与设计书 §7.5 隐私最小化对齐，不许放宽）

1. **匿名到底**：不署名、不收姓名/联系方式（投稿系统只给一个投稿编号）；地名只到城市层级，单位、学校一律化名或泛化（「一家大厂」「一所中学」）。
2. **双重同意、分开勾选**：①同意在故事墙发布；②同意被改编进游戏事件库。两个同意独立，缺一不可代偿；反思文字（局内给自己留的话）默认永不投稿，必须玩家主动走投稿流程另行授权——结算页不许放「一键把这局发到故事墙」。
3. **可撤回**：投稿时给撤回口令（玩家自设词 + 投稿编号），撤回即下线并在事件库下一版移除改编条目，页面写明这一条。
4. **审核红线**：涉及自伤、未成年人亲密关系、具体医疗建议的故事不收；沉重故事按设计书 §7.2 敏感协议编辑（写事不写惨），发布前给投稿人看一遍编辑稿（通过投稿编号回查页确认）再上线。
5. **未成年**：投稿声明限 18 岁以上；故事墙定位是成年人的回望，不做青少年投稿。

## 4. 指标：上线后看哪 6 个数（口径、健康线、kill/pivot 线）

前置（P0）：先上匿名埋点（SCALING L2 口径：隐私友好统计或自建小口子），事件至少含 `visit / start / era_span_selected / complete / share_panel_open / share_action{system,copy,save} / challenge_link_copy / challenge_land / challenge_start / daily_seed_start / keepsake_purchase`。无账号、无指纹、只报事件与参数（年代/跨度/卡型/钩子版）。**埋点没上线，以下指标除完局率外都不许对外引用。**
