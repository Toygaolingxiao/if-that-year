# 全量文本长度治理（用户指令，2026-11-03）

**起因**：用户凌晨实机试玩，当面指出开局首屏废话太多，并下令整体治理——所有文本都要避免太长，可开多个作家 agent 并行改，全程用人类语言。

## 现状实测（2026-11-03 主代理机械统计，只读）

- 事件正文 `text`：2,316 条，中位 73 字，p90 103 字，最长 152 字，超 120 字的 34 条。单条正文本身不失控。
- 选项 `label`：最长 39 字，健康。
- **真正的病灶有三**：①说明性页面（首屏两段规则讲解约 150 字，已在 v0.20.1 返修轮内处置）；②叠屏——分岔题面+回响、进程拍与事件同屏、结算九槽叠加，一屏总量没人管过；③长尾——超 120 字的正文与各 lines/进程/序章文本从未做过全量普查。

## 预算（按类，硬线须逐条达标或登记特批理由）

| 类 | 目标带 | 硬线 |
|---|---|---|
| 事件正文 text | 40–85 字 | 110 字 |
| 选项回响 echo | ≤45 字 | 60 字 |
| 选项 label | ≤16 字 | 20 字 |
| 序章拍 text/log | ≤70 字 | 80 字 |
| 进程拍 / 线文本 | ≤80 字 | 90 字 |
| 结算单槽 | 一句 | 60 字 |
| 分岔题面 | ≤80 字 | 90 字 |
| 首屏正文 | 一句 | 60 字（已在修） |
| 叠屏（一屏总量） | 题面+选项或正文+回响合计 | 软线 220 字，超线逐屏登记 |

## 施工法

- **多个作家 agent 并行**，按领地切分（事件池前半 / 事件池后半+稀有+年代包 / lines 与进程与结算 / 序章与分岔与界面串），各领一份预算表与 flagged 清单。
- **作家只许做两件事**：缩短、顺句。门、数值、旗标、事实、人物关系一律不许动；删掉的每一句都要确认信息已由别处承担或本就是废话。
- **人类语言**：全程照 docs/COPY-AND-AI.md——具体场景优先，禁词表照旧，改完每条默读出声检查；缩短不许把人话缩成电报腔，宁可删整句，不许把句子剁成碎片。
- 作家之间不许互相参考改法（各领地独立判断），协调者最后统一复核口径。

## 验收

- 全量复测：按类出改前/改后分布（中位、p90、最长、超线数），超线残余逐条带特批理由登记。
- quality-gate 全套回归不倒退；同种子复跑确认无文本截断事故（引用、槽位、回响挂接）。
- 抽 30 条改过的文本给一名全新评审盲读：只判一件事——还像不像人说的话。
- 版本号随轮次定（独立成轮为 v0.20.2），DEVLOG 记一条。
