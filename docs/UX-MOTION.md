# 交互与动效改进方案

> 本文只谈手感：画面怎么切换、数值怎么反馈、手指点下去发生了什么。
> 内容、文案、数值规则不在本文范围。所有现状描述均按 2026-10-31 的代码实测（src/engine.js v0.7.0、src/style.css、index.html），不凭印象。
> 前提：自动推进三态（关/平年/全程）与桌面双栏已在另一条线落地，本文不重复提案，只在其之上找增量。

## 现状核对摘要（写方案前先对账）

- 全站渲染方式是整卡 `innerHTML` 全量替换；`.card` 带 `rise` 动画（淡入＋上移 8px，350ms）。注意：VISUAL-DESIGN §一.5 写的纪律是「淡入＋上移 4px，≤200ms」，代码已经漂到 350ms/8px，文档和实现对不上。
- 五维条 `.bar i` 写了 `transition: width .6s ease`，但每次渲染都是新建元素并直接写入最终宽度，没有「旧值→新值」的变化过程，这条过渡在绝大多数浏览器里根本不会播放——写了等于没写。数值变化目前唯一真实可见的反馈是 `.delta` 一行小字（如「健康 +5 · 金钱 -3」）。
- 选项按钮 `.choice` 只有 `:hover` 样式（边框变松绿＋右移 3px），没有 `:active` 按下态，没有 `:focus-visible`，选中后也不保留任何选中痕迹：普通事件是点完立刻移除按钮组、换上回响区；分岔更干脆，点完直接进下一年，连回响拍都没有。
- 自动推进的倒计时没有任何剩余时间可视化：计时中只有 autorow 里一个闪烁圆点＋「自动推进中」五个字。游戏内 autorow 的按钮是 12px 字、`padding:2px 3px`，实际命中高度约 16px。
- 流水账每次推进都无条件 `scrollTop = scrollHeight` 瞬时跳到底，玩家上翻查账时会被下一年强行拽回去。新行提示只有最后一行的底色高亮。
- 结算页是整页一次性倒出：标题、判词、影子对照、分享台、年表同一个瞬间全出现，没有揭示顺序，也谈不上跳过。
- 全站没有任何 `prefers-reduced-motion` 处理；页脚小字 `#A39C8B` 在纸色上对比度约 2.4:1；index.html 页脚还写着「原型 v0.5」，与引擎 v0.7.0 脱节。
- 好的一面先说清：存档每一步静默保存、续玩按钮自带「年龄·路线」定位信息、全程模式点任意处暂停、瞥视卡「看/不看」一样大——这些现状是对的，本文不动它们，只补缺口。

## 参考手法（研究笔记）

同类产品解决同类问题的通行手法，方案条目里只写方案本身，这里集中记来源：

- 视觉小说的引擎惯例（Ren'Py 一系）：auto 是「等文字显示完再停顿」的阅读速度概念，配套 backlog（历史回看）和 skip（跳过已读）。给我们的启发是：自动推进的停顿应该跟内容长度走（我们已经按字数加时，方向一致），以及回看历史时不该被新内容打断。
- 卡片叙事游戏 Reigns：选项的后果在**选择之前**就以小圆点暗示会影响哪几项数值，按压时卡片倾斜跟随手指。它证明了「反馈前置＋按下有形变」对决策类小游戏的手感提升最大。
- inkle 的文字冒险（80 Days 等）：新段落以段为单位轻淡入，不逐字；选择后旧文上移让位。它证明了段落级淡入足够，逐字打字机不是必需。
- 阅读类应用（Kindle、微信读书）：进度用一条极细的线表示，续读时给出「上次读到」的位置标记，从不弹提示框。这两招分别对应我们的倒计时细线和续玩定位。
- 放置/增量游戏（Universal Paperclips 一系）：数字跳动和浮动增减提示是那类游戏的核心快感来源，但它们的气质是仪表盘——正是本项目明确不要的。所以那套手法本文只借「变化要看得见」这一条原则，具体形式不用。
- 平台规范（Apple HIG、Material Motion）：微交互时长普遍在 100–300ms；`prefers-reduced-motion` 是系统级约定，减动效时保留功能、去掉位移和闪烁。这两条作为本文的硬尺子。

## 1. 画面切换

### 1.1 普通年份不要整卡重播入场动画

- 问题：每推进一年，整张卡（含路图、五维条、meta 行这些没变的「卡壳」）都重播一次 350ms 的 `rise`。一局四十多年，等于同一个淡入看四十多遍；而且头部明明没动，看起来却像整页刷新，眼睛每年都要重新定位一次选项区。
- 方案：分级入场。卡壳（路图、五维、meta、autorow）只在画面类型变化时（开局→游玩、游玩→瞥视/危机、进结算/死亡）播入场；同类年份之间只让正文区与选项区淡入 150ms，卡壳原地不动。实现上给 `.card` 加一个「静态」变体类，同类推进时用它，动画只挂在 `.body`/`.choices` 上。同时把 `rise` 参数收回纪律内：4px、200ms 以内。
- 为什么更舒适：眼睛的锚点（五维条位置）不漂移，年与年之间是「翻了一页纸」而不是「重开了一页纸」；动画回归到只提示「有新内容」这一件事。
- 成本：中（要改渲染结构，`head()` 与正文要分开控制动画类）。
- 适用画面：游玩页全部年份卡。

### 1.2 结算页分段揭示，且随时可跳过

- 问题：结算是一生一次的高潮页，现在标题、判词、影子对照、分享台、几十行年表在同一帧全砸出来，玩家第一眼不知道先看哪，最重要的判词被淹没在信息量里。
- 方案：按阅读顺序分四段揭示——标题与路（结算图，见 §9.2）→ 判词 → 影子对照（含瞥视留言）→ 分享台与年表。每段间隔约 120ms 依次淡入，总时长控制在 700ms 内；揭示期间点页面任意处，立即全显（跳过）。分享台和年表这两段工具区也可以直接全显、不参与揭示，仪式只留给前两段——两种切法都可，建议先按四段做，嫌慢再收。
- 为什么更舒适：先给结论（这一生走完了、判词是什么），再给对照，最后才是工具和细账，视线有路可走；可跳过保证老玩家重开时不被迫看仪式。
- 成本：小（结算页各块加 `animation-delay` 递增＋一个「点击全显」的类切换）。
- 适用画面：结算页；死亡结算同理（死亡卡本身是单独一拍，已成立）。

### 1.3 展开类内容（瞥视细节、回响）统一淡入

- 问题：瞥视点「看细节」后，细节区是瞬间换 `innerHTML` 出现的；事件回响区同理。内容凭空蹦出来，与纸面气质不合。
- 方案：给 `.echo`、`#detail` 的内容统一挂 200ms 淡入（复用收过参数的 `rise` 或一个纯 opacity 版）。不做高度展开动画（内容高度不定，硬做会抖）。
- 为什么更舒适：注意力被轻轻领到新出现的那段字上，不用自己找「刚才点完之后页面哪变了」。
- 成本：小。
- 适用画面：瞥视卡、事件/危机/稀有事件的回响区。

## 2. 数值反馈

### 2.1 先把五维条的动画修成真的

- 问题：如现状摘要所说，`width .6s` 过渡因全量重建从不触发；玩家感知数值变化只能靠读 `.delta` 小字和自己比数字。
- 方案：二选一，推荐前者。甲：渲染后先以旧值写条宽，下一帧（`requestAnimationFrame`）再写新值，让既有 0.6s 过渡真正播放；旧值从渲染前的状态快照取。乙：删掉条过渡，只保留 delta 行。明确不做的丙：数字滚动计数——等宽数字逐格跳动是仪表盘语言，与「数值是日子，不是 KPI」的既定口径冲突。
- 为什么更舒适：条长变化是余光就能捕捉的信号，尤其健康、金钱这种大起大落，眼睛不用逐字读完 delta 也知道「刚才那下伤着了」。
- 成本：小（甲方案十几行）。
- 适用画面：所有带五维条的卡。

### 2.2 delta 行的呈现节奏

- 问题：delta 行只有一行等宽小字，出现在正文下方，和正文没有视觉分工；选完选项后它出现在回响区顶部，是对的，但出现方式是瞬时的，容易被跳过。
- 方案：delta 行随回响区一起淡入（并入 §1.3）；正负号保留现状（已有 `+`/`-`）；负数不改红字、不加警告色——松绿与墨色足够区分，红字会把日子变成成绩单。停留时长不单独设计：它活在回响画面里，玩家点「过一年」之前一直在，这已经够了，不需要再做「3 秒后消失」式浮层。
- 为什么更舒适：变化在玩家做完选择的同一拍出现、且停在眼前，而不是飘过去；不变色保住了判词那套「无尊卑」的气质——数值掉了是日子的一部分，不是判错。
- 成本：小。
- 适用画面：事件、危机、稀有事件的回响拍。

### 2.3 临界与危机的提示分级（静态分级，不闪烁）

- 问题：现在提示强度只有两档——平时什么都没有，危机来了整张卡换个边框色。中间地带（比如健康已经跌到 20 出头、离危机不远）玩家毫无察觉，危机触发时会有「怎么突然就」的突兀感。死亡系统又恰恰挂在「健康 <25 且被危机警告过」上，临界提示缺位会让早夭显得没来由。
- 方案：三级，全部用静态手段。一级（某维 <30）：该维在五维条里数字加粗、条尾加一个墨色小点，常驻不闪。二级（危机卡）：保持现有边框色与 head 注，入场动画换一个「沉」的变体（从下方 2px 淡入，不上浮），与普通年份区分。三级（死亡）：已有独立终局卡，足够，不再加码。
- 为什么更舒适：坏消息是逐级走近的，玩家在危机真正到来前已经在余光里见过提醒；全程没有任何闪烁、震动、变红，紧张感来自动作变「沉」，不是报警。
- 成本：小（一级是 statsBar 里一个条件类；二级是一个动画变体类）。
- 适用画面：五维条（全卡通用）、危机卡。

## 3. 选择反馈

### 3.1 补按下态与焦点态

- 问题：`.choice` 没有 `:active`，手机上点下去到页面变化之间有一小段「什么都没发生」的空白；键盘/读屏用户也没有可见焦点。`.primary`、`.ghost`、`.segbtn` 同样缺 `:focus-visible`。
- 方案：全站交互元素补两条：`:active` 时背景变 `#F6F3EC`、边框变松绿（100ms)；`:focus-visible` 时 2px 松绿描边＋2px 偏移。hover 的右移效果包进 `@media (hover:hover)`，避免触屏点后粘滞在偏移状态。
- 为什么更舒适：按下立刻有回应是手感的地基，尤其本游戏一局要按几十次；成本几乎为零，没有理由不做。
- 成本：小（纯 CSS)。
- 适用画面：全部按钮与分段选择。

### 3.2 手动选择后要留一拍「你选了什么」

- 问题：普通事件选完，按钮组被整体移除，回响直接出现——玩家对「我刚才点的是哪一条」没有确认感，手快时甚至怀疑自己点错了。全程自动选反而有 `.autonote` 写明「已选『X』」，手动选倒没有，这是个不一致。
- 方案：统一一拍：点击后，被选按钮先置为选中态（松绿填充，复用 `.segbtn.sel` 的视觉语言）停留约 250ms，其余按钮淡至半透明，然后才换回响区；回响区顶部固定一行小字复述所选（与 autonote 同位置、同格式，手动版不带「自动推进·」前缀）。分岔与危机、稀有选项同一处理。
- 为什么更舒适：选择是这个游戏的核心动作，值得有一拍确认；250ms 不拖节奏，又足够让眼睛登记「选的是这条」。
- 成本：小（点击处理里加一个短延时与类切换；注意自动推进计时要在这一拍里保持暂停，现已有 clearAuto 逻辑可复用）。
- 适用画面：事件、危机、稀有事件的选项。

### 3.3 分岔口要有全游戏最重的反馈，而不是最轻的

- 问题：分岔是 8 个「大选择」，现状却是点完直接 `advance()` 进下一年——没有回响、没有停留、连所选都没复述，全游戏最重要的决定反而最无声。普通事件都有回响拍，分岔没有，轻重倒置。
- 方案：最小版先行：分岔点击后走 §3.2 的同一拍（选中态 250ms），然后在进入下一年之前插入一个复述拍——卡上只留一行「你选了『X』」＋「过一年」按钮，与事件回响同构，不动数据结构。完整版（等内容侧给分岔选项补 echo 文案后再做）：分岔回响用独立的一段文字，权重高于普通事件。
- 为什么更舒适：玩家会在分岔口停下来想，界面也应该在那里停一拍；复述拍同时解决了「手滑点错分岔」无可挽回的懊恼感——至少他看清了自己选了什么。
- 成本：小（最小版）；中（完整版，卡在文案数据）。
- 适用画面：8 个分岔口。

## 4. 自动推进舒适度

### 4.1 剩余时间画成一条细线

- 问题：计时中只有一个闪烁圆点，玩家不知道这一年还剩 2.5 秒还是 0.3 秒，读长事件时心里没底，怕没读完就翻页——这种不确定感本身就是交互摩擦。现已有 `autoRemain`/时间戳等内部状态，缺的只是把它画出来。
- 方案：autorow 下缘（或卡顶）加一条 2px 细线，松绿、约 40% 不透明度，宽度从 100% 线性收尽到 0，时长等于本屏总停留（含字数加时）。实现用 JS 已有计时状态驱动：起计时时给细线设 `transition: width <剩余>ms linear` 并把宽度置 0。切速度档/模式时按新总时长重启细线——先无过渡地复位再起线，避免宽度回跳。暂停（切后台、点暂停）时细线冻结在当前宽度（getComputedStyle 取值后固定），恢复时按剩余继续。
- 为什么更舒适：阅读节奏变成可预期的——瞥一眼线就知道「这段读得完」；细线是纸面语言（一条墨线慢慢收短），不引入环形进度、百分比数字这类仪表盘元素。
- 成本：中（计时状态与细线的暂停/恢复同步要仔细，引擎里已有 pause/resume 骨架，是顺着加）。
- 适用画面：所有可自动推进的画面（平年全程两模式）。

### 4.2 暂停的命中区要够大

- 问题：全程模式有「点任意非控制区即暂停回手动」，很好；但平年模式想暂停只能点 autorow 里 16px 高的小字按钮，手机上基本点不准。autorow 按钮本身在所有模式下都太小。
- 方案：两步。① autorow 内按钮视觉字号不变，`padding` 提到上下 10px、左右 6px，命中高度到 40px 以上，行距用负 margin 收回，不撑高版面。② 平年模式补齐与全程一致的暂停手势：点正文区（非按钮、非选项区）即暂停本屏计时并切到关——语义与全程统一，玩家不用记两套。
- 为什么更舒适：暂停是自动推进的安全阀，必须在慌的时候一击必中；命中区只在触摸层放大、视觉不变密，版面气质不受影响。
- 成本：小。
- 适用画面：游玩页 autorow 与正文区。

### 4.3 全程模式自动选，要让玩家看见「手落在哪」

- 问题：全程模式到点自动选一项时，按钮组是直接被移除换回响的，玩家只在回响里读到 `.autonote` 才知道选了什么。结果没错，但过程是跳变的——尤其选项里有他其实想选的那条时，会有被替他做主的错觉。
- 方案：自动选的执行拆成两段：计时最后 400ms，被选中的按钮提前进入选中态（同 §3.2 的松绿填充），其余变淡；到点后才换回响区，autonote 保留。相当于把手动选的那一拍借给自动选。
- 为什么更舒适：玩家能预判「它要选这条了」，不合意时在 400ms 内点任意处就能夺回手动——控制权一直在玩家手里，自动只是代劳，不是代决。
- 成本：小（自动选动作前加一个预高亮定时器；与 §4.1 细线在最后 400ms 的表现天然衔接）。
- 适用画面：全程模式的普通事件选项。

### 4.4 切档不跳变（现状已对，只需守住）

- 问题：无。现状切模式/速度都走 `scheduleAuto()` 按新档重排计时，是对的。
- 方案：不新增；只要求 §4.1 细线落地时遵守同一原则——任何切换都从新总时长干净重启，不出现线宽回跳或剩余时间错乱。
- 成本：小（约束，随 §4.1 一并验收）。
- 适用画面：autorow、开局页速度分段。

## 5. 流水账阅读

### 5.1 玩家上翻查账时，不要把他拽回底部

- 问题：`mountStream()` 每次推进都无条件滚到底。玩家想回看三年前那件事，刚翻上去，下一年一刷新就被瞬时拽回——查账这个动作基本被废掉，而查账恰恰是这个游戏后半程最常见的动作（「那年那件事是几岁来着」）。
- 方案：跟随状态机。距底小于 40px 视为「贴底跟随」，新行时继续滚到底；一旦玩家上翻超过这个距离，切到「自由浏览」，新行不再滚动，改为在流水账标题旁出现一个静态小提示「有新的一年 ↓」，点它（或自己滚回底部）恢复跟随。宽屏双栏与窄屏卡内两种形态同一逻辑。
- 为什么更舒适：这是阅读类产品处理「后台还在更新的列表」的标准解法：系统不跟读者的手抢滚动条。玩家查完账，一键回到最新，账本始终是他的。
- 成本：小到中（一个滚动监听＋一个状态位＋一个提示元素）。
- 适用画面：游玩页流水账（双栏/单栏）。

### 5.2 跟随滚动要缓，不要瞬移

- 问题：现状 `scrollTop = scrollHeight` 是瞬时跳，贴底跟随下每年跳一次，眼睛要重新找行。
- 方案：贴底跟随时改用平滑滚动（`scrollTo({behavior:"smooth"})` 或等价的 200ms 缓动）；若新行距当前视口超过一屏（比如切后台回来积压了多年），直接瞬时到位，不滑行穿越大段内容。减动效模式下永远瞬时（见 §8.1)。
- 为什么更舒适：新行是「滑进来」的，上一行还在视野边缘，阅读的连续性不断；这也是「账本在自己生长」的纸面感的一部分。
- 成本：小。
- 适用画面：流水账。

### 5.3 新行入账的提示保持现状，只补自由浏览态

- 问题：现状最后一行有底色高亮＋淡入，够了；缺的只是 §5.1 自由浏览态下「有新行」的知会。
- 方案：不新增动画形式，复用 §5.1 的标题旁提示即可；高亮行在被看到前保持高亮（现状是只有渲染时最后一行高亮，自由浏览态下新行追加后「最后行」会变——要求高亮跟随「未读的第一行」，或简单处理：自由浏览态下新行都带高亮，玩家滚回底部后清除）。
- 为什么更舒适：不引入红点、角标这类应用语言；一个账本只需要告诉你「新账记在哪页」。
- 成本：小（随 §5.1 一并做）。
- 适用画面：流水账。

## 6. 开局与加载

### 6.1 没有加载问题，就不要造加载仪式

- 问题：无。单文件同步脚本，打开即开局，没有网络等待；现状也没有骨架屏和开场动画，这是对的。
- 方案：不新增任何开场动画、品牌闪屏、骨架屏。唯一建议补的是健壮性：点路线开局的那一拍给按钮组加短暂禁用，防止双击连点在同一帧触发两次开局。
- 为什么更舒适：「选路即开局」是已裁定的开局原则，中间塞任何仪式都是倒退；打开就能玩本身就是这个形态最大的体面。
- 成本：小（防连点）；其余为零。
- 适用画面：开局页。

### 6.2 续玩进来，要有一句「你回到哪了」

- 问题：续玩按钮本身带「27 岁 · 出国，从头开始」，点之前定位是清楚的；但点进去直接落在当年卡上，隔了几天回来的玩家要自己从流水账里数「我玩到哪了、之前都选过什么」。
- 方案：续玩进入后的第一屏，在 meta 行尾加一句静态小字「（上次玩到这里）」，只出现这一次，下一年自动消失；流水账保持贴底跟随，让他先看见最近两三年的账。进一步的「前情提要」卡不做——那是新仪式，且流水账本身就是提要。
- 为什么更舒适：续读产品的通行做法就是给一个位置标记，不打断、不弹窗；一句话的成本，省掉玩家自己翻账找进度的时间。
- 成本：小。
- 适用画面：续玩后的第一张卡。

### 6.3 存档安全感：继续静默，不加提示

- 问题：无。现状每一步自动存档且全程无提示，有人会担心「没存上怎么办」，但解法不是加提示。
- 方案：不做「已保存」吐司、不做存档图标动效。每一步都弹一次保存提示是纯噪声；真正的安心来自行为本身——关掉重开，续玩按钮就在那儿写着岁数。维持现状，并把它写进不做清单防以后手痒。
- 成本：零。
- 适用画面：全站。

## 7. 移动端

### 7.1 命中区审计：三处不达标

- 问题：按 44px 最小命中这条通行线实测现状：`.choice`（含文字两行时约 55px 以上，达标）、`.primary`（约 45px，达标）、`.segbtn`（padding 8px 13px，约 36px，不达标）、autorow 按钮（约 16px，严重不达标，见 §4.2）、`.ghost`（约 43px，临界）。开局页的年代与自动推进分段是玩家每局必点的，不能只有 36px。
- 方案：`.segbtn` 上下 padding 提到 11px；autorow 按 §4.2 处理；`.ghost` 上下 padding 微增 1px。视觉尺寸几乎不变，只补触摸层。
- 为什么更舒适：点不准的挫败感是隐形的，玩家不会说「按钮太小」，只会觉得「这游戏有点笨」。命中区是最便宜的手感。
- 成本：小（纯 CSS)。
- 适用画面：开局页、结算分享台、游玩页 autorow。

### 7.2 安全区与输入框字号两个小口子

- 问题：viewport 没有 `viewport-fit=cover`，全站没用 `env(safe-area-inset-*)`，刘海屏上底部内容可能贴到手势条；种子输入框 15px，iOS Safari 聚焦小于 16px 的输入框会自动放大页面（留言输入框是 16px，没这问题，就差这一个）。
- 方案：viewport 加 `viewport-fit=cover`；`.wrap` 与 `.foot` 的底部 padding 改为 `max(原值, env(safe-area-inset-bottom))`；种子输入框字号改 16px。
- 为什么更舒适：都是「不做就会偶尔膈应一下」的小口子：页面被输入法莫名放大一次，玩家对手感的信任就掉一截。
- 成本：小。
- 适用画面：全站、开局页种子行。

### 7.3 单手操作：主要动作已在拇指区，暂停不在

- 问题：选项与「过一年」都在内容流下部，单手可达，这点现状是好的；但暂停自动推进的入口在卡片顶部的 autorow，单手握持时是最远的位置。
- 方案：不搬 autorow（它同时是状态显示，放顶部是对的）；靠 §4.2 的「点正文暂停」解决够不着的问题——暂停的手势落在拇指区，状态显示留在顶部，两件事分开。
- 为什么更舒适：高频动作（继续、选择、暂停）全在下半屏，低频动作（切档、切速度）留在顶部细行，符合单手使用的频率分布。
- 成本：小（随 §4.2)。
- 适用画面：游玩页。

## 8. 无障碍与减动效

### 8.1 补 `prefers-reduced-motion` 降级

- 问题：全站零处理。系统里开了「减少动态效果」的玩家，现在照样吃满 `rise` 位移、圆点闪烁（`autoblink` 1.1s 无限循环）和条宽过渡；无限闪烁对一部分人是实打实的不适。
- 方案：加一条全局媒体查询：`rise` 改为纯淡入（去位移）或直接无动画；`autoblink` 停（圆点常亮表示计时中）；条宽过渡改瞬时；流水账平滑滚动改瞬时；结算分段揭示改同屏出现。功能一个不少——自动推进照常走，只是所有「动」降为「变」。§4.1 的细线在减动效下改为分段跳变或干脆只保留圆点静态显示，二选一，推荐保留细线但无过渡地跳变（信息还在）。
- 为什么更舒适：这是系统级约定，玩家在系统里已经表过态，产品要听；降级路径都在既有机制内，不需要另做一套界面。
- 成本：小（一处媒体查询＋细线的一个分支）。
- 适用画面：全站。

### 8.2 对比度与字号底线

- 问题：页脚 `#A39C8B` 约 2.4:1，不及格；`.hint` 本身是 `--mut`（约 4.9:1，及格线边缘）又叠了 `opacity:.85`，实际对比被拉到线下；流水账年份 11.5px、meta 12.5px、autorow 12px，都是辅助信息但已在舒适阅读的下限之下。
- 方案：页脚改用 `--mut`；`.hint` 去掉 opacity（或颜色加深一档补偿）；辅助文字底线定为 12px，年份等宽字 11.5→12px。正文 16.5px、选项 15px 现状良好，不动。
- 为什么更舒适：这个游戏的目标玩家里有大量中年以上（年代模式就是为他们做的），小字低对比对他们不是「精致」而是「看不清」；底线只抬一档，不伤版面。
- 成本：小（纯 CSS 数值）。
- 适用画面：全站辅助文字。

### 8.3 焦点可见性

- 问题：全站没有 `:focus-visible` 规则，键盘与开关控制用户 Tab 过去只能靠浏览器默认描边，而卡片圆角与默认描边贴合很差。已并入 §3.1 一并处理，此处只登记：验收时按全站过一遍，不只选项按钮。
- 成本：小（随 §3.1)。
- 适用画面：全站。

## 9. 路图与结算图的生长

### 9.1 游玩页小路图：接受跳变，只补当前点

- 问题：游玩页顶部路图每次渲染按当前年龄静态重绘，松绿线一年跳长一截，当前点直接出现在新位置。作为进度指示它够用，跳变谈不上难受；硬给整条线做位移过渡，要保存旧位置再插值，收益和成本不成比例。
- 方案：只给当前点补一个 200ms 的轻淡入（新点出现时从 0.6 透明到实），线长跳变保持。或什么都不做——本条的结论是「低优先，先放着」。
- 为什么更舒适：当前点是这张图里唯一的「活物」，它出现得柔和一点，整张图就不显得是硬切换；再多就是给进度条配动画了，过。
- 成本：小（做淡入版）；中（若日后要做插值位移，再单独立项）。
- 适用画面：游玩页路图。

### 9.2 结算纵轴图：线自己画出来，是全产品唯一值得做满的动效

- 问题：结算纵轴图已裁定待落地（VISUAL-DESIGN 第四节）。它如果落地时是静态一次出现，就浪费了这个位置——结算是玩家唯一会停下来慢慢看、还会截图的画面，签名动效（画轴展开/线条生长）就该用在这里，而且只用在这里。
- 方案：随结算图落地一并实现，一次性的生长仪式：中脊用描边生长（`stroke-dashoffset`）自上而下画完，全程约 900–1200ms；支流在中脊画到其分岔点时依次短画并淡入，分岔小字随支流出现后再迟 100ms 淡入；早夭的局，中脊就停在那一年，剩余纵轴留白不画——留白本身就是内容。交互：点图任意处立即全显（跳过）；与 §1.2 的揭示顺序咬合为：标题→图生长→判词→对照→记录。与 §8.1 咬合：减动效时整图静态呈现。
- 为什么更舒适：一生被「写」出来的那一分多钟（实际一秒上下）是这个游戏最值得慢的地方；可跳过保住了重开玩家的耐心；这也是四张样稿里「画轴慢慢推开」那个诉求的正解落点——动效集中在一处、用在高潮、用完即止。
- 成本：中（随结算图落地一并做，不单独立项、不提前做）。
- 适用画面：结算页纵轴图；分享卡是静态 PNG，不受影响。

### 9.3 游玩中的路「生长感」不另做

- 问题：曾有方向想让游玩页的图随年龄持续生长成主角。已裁定游玩页只是简洁进度图（定位见 VISUAL-DESIGN 第四节），本文确认不再提案：持续生长会和「卡壳不动」（§1.1）打架，也会抢正文的注意力。
- 方案：不做。生长仪式只属于结算（§9.2)。
- 成本：零。
- 适用画面：游玩页。

## 不做清单（明确表态，防以后反复）

| 不做 | 理由 |
|---|---|
| 打字机逐字显示 | 正文是百字级散文，逐字会拖慢阅读、和自动推进按字数计时互相打架；视觉小说的逐字是为配音与演出节奏服务的，本产品无配音、重回看，段落级淡入（§1.3）已经够了 |
| 音效（翻页音、点击音、环境音） | 默认静音是既定的人文体面（VISUAL-DESIGN §一.5 已定）；纸感产品一旦出声就廉价，且公共场合玩家多为静音游玩，做了也听不见 |
| 震动反馈 | iOS Safari 不支持 `navigator.vibrate`，双端不一致；气质上与「日子」主题相冲，危机靠边框和文案已经足够 |
| 稀有/特殊结局的粒子、金光、闪烁特效 | 稀有卡已有金边＋浅金底，信息层级清楚；特效会把「这一年不太一样」做成抽卡爆率展示，与结局无尊卑直接冲突 |
| 3D 翻页、卡片翻转 | 与签名动效（纸面生长）重复且更重；翻页感已由 §1.1 的分级淡入以更低成本实现 |
| 危机/死亡时的屏幕震动、红闪 | 告警靠静态分级（§2.3）与独立终局卡；震动红闪是恐怖游戏语言，用在这里是惊吓，不是提醒 |
| 五维数字滚动计数 | 等宽数字逐格跳动是仪表盘语言，与「数值是日子，不是 KPI」冲突；变化可见性由条宽过渡（§2.1）承担 |
| 骨架屏、开场动画、品牌闪屏 | 没有异步加载，做即是造假；且违背「选路即开局」的已裁定原则 |
| 「已保存」吐司/存档动效 | 每步弹一次是纯噪声；安心感来自续玩按钮一直在（§6.3） |
| 下拉刷新、上滑切年等手势推进 | 与页面滚动、流水账滚动必然打架，误触代价高；推进已有按钮与自动两条正路 |
| 动态分享卡（GIF/视频出图） | 出图管线是静态 Canvas 一张图，动图要整条重做且各平台压缩后质感不可控；静态判词卡的传播形态已经成立，不为动效推翻 |
| 成就弹窗、连玩天数、回访红点类留存钩子 | 与产品气质和既定留存口径（靠今日种子与同局对战，不靠打卡）不符，不属于手感范畴，列此防顺手引入 |
