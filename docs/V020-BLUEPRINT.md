# v0.20 整合蓝图：从碎片到一个整体

用户授权（2026-11-02）：最大权限改进，可拆大文件、可重构；目标 v0.20.0 达到「一定程度可公开」。本蓝图是 v0.20 轮的施工宪法：先吸收 galgame 事件树调研的可搬部分，再把 v0.13–v0.19 碎片化攒下的结构整合成一张总图。

## 〇、产品方针（用户 2026-11-02 定，最高口径，冲突时以此为准）

**一句话能懂，每次结果不同，结果与玩家有关，玩完特别想截图发给别人。**

四条各有落点，不许只当口号：
- 一句话能懂 → 首屏与对外介绍只用一句话讲清玩法（「如果那年你选了另一条路，这一生会怎么过完」这一型）；讲不清就改产品呈现，不怪玩家。
- 每次结果不同 → 局与局的差异要有可数证据（结局组合分布、人格间结局距离），不是换皮随机。
- 结果与玩家有关 → 结算只许用这一局玩家自己的事实拼装（九槽口径），出现与玩家无关的通用判词即缺陷。
- 想截图发给别人 → 结算屏即截图面：分享卡与人生年表按「玩家会想截下来发出去」的标准设计与验收。

## 一、目标

v0.20.0 = 第一个可公开版本。陌生人打开链接，能完整玩完一条命，不撞见逻辑硬伤，玩完愿意分享。是否达标按第六节清单逐项验，逐项要有证据，不许自评；第六节之外，〇节四条方针是总验收，任一条立不住就不算可公开。

## 二、碎片盘点（v0.13–v0.19 各攒了什么、以什么形态存在）

- **两套开局并存**：v0.13 卡牌开局（cards.js）与 v0.17 序章（prologue.js，只 c2000 退役了卡牌，其余年代仍是卡牌）。
- **两套状态并存**：历史旗标系统 + v0.18 状态矩阵/结构化账本。旗已降级为里程碑，但事件条件仍大量读旗；8 个状态域 + 父母进程 + 工作相位（v0.19 在补）各写各的。
- **事件池按批次长**：packs 按开发批次编号（pack13/15/20/29…），不是按领域。同主题散在多包；包内默认人生互斥（v0.19 以职业旗治大半）。
- **抽取顺序写死**：门过滤 + 加权随机 + chain 保底的顺序管线埋在 engine.js 里；温度（rhythm.js）是外挂参数，各处散读。
- **结局两套并行**：特殊结局 17 个 + 九槽拼装走账本；synergy.js（组合/稀有）是 v0.15 的独立模块，与账本口径并行。
- **大文件**：engine.js 2081 行（抽取、进程、呈现、结算、存档全在一起）；registry.js 1559 行（注册数据 + 校验逻辑混杂）。
- **文档 23 篇**：现行的（FOUNDATION / KERNEL 引用 / STATE-MATRIX / MORTALITY）与历史的（DESIGN-V013、REVIEW-*、WAVE 半截稿）混放，口径散在 DEVLOG 里。

碎片感不在任何单件，在于没有一张总图把关系写死：每次改动都要在脑子里重建全图，这是效率的漏点，也是状态线类 bug 反复换马甲出现的原因。

## 三、吸收的十条（galgame 调研 → 本作的落法）

出处：~/workspace/research_notes/galgame-event-tree-design-20261101-2211/report.md 第三节。

1. **storylet 原子模型 → 统一事件模式**：全池条目（普通事件、序章拍、进程发声、链拍、稀有拍）一律同一份字段：id / 域 / 年窗 / 语境门（ctx）/ 优先级层 / 效果（只许写状态域或立里程碑旗）/ 后继链。v0.19 的 ctx 与职业旗是雏形，v0.20 立为唯一模式，校验器按模式验全池。
2. **日历骨架 + 条件池 → 年代锚点表**：每个年代一张锚点表（入学、成年、时代节点、退休、父母进程关键点），锚点占调度 L0 必经（只按状态换皮）；锚点之间全是池。散在各包里带「必经感」的事件收进锚点表，其余降为池条目。
3. **五层仲裁 + saliency → 抽取层重构**（内核二期原定项，提到 v0.20）：L0 锚点独占 > L1 危机抢占（带截止期）> L2 支线链推进 > L3 日常/关系（saliency：条件具体度计分最高者胜，其次最久未见）> L4 随机风味（只填空槽、不写关键旗）。温度改为调度层的输入（决定 L3/L4 密度与静年份额），derive 收进调度器，结束各处散读。
4. **阈值单调 → 常设门**：v0.19 阈值检查已跑（A 链式翻转 0、B 同组挤压 0、C 多高门槛同立 2）；v0.20 把 threshold-check 并入常设质量门，每轮必跑。
5. **延迟分歧清点**：凡「早年选完立刻开线结死」的叉，改成立状态、晚年结算，与九槽同向。fork16、序章选择、fork38 立约已有雏形，本轮做全清点并逐条登记处置。
6. **可见检定**：玩家被期望规划的事（入行、生育窗口、父母照护），门槛与检定结果要可见；藏后果，不藏检定。入设计口径；v0.20 只落最明显的几处提示（入行拍的去向说明、fork45 窗口期提示、照护进程的预警）。
7. **旗标纪律收口**：旗只许里程碑语义；写入点只许「选择直后 / 事件结束」两处，校验器查写入点；元进度（往世录、连续游玩）与局内状态分开存（现已分开，做一次口径复核）。
8. **模型检验一键化**：validate-state + 时代扫描 + 职业预设扫描 + 状态线冲突扫描 + 阈值检查 + 16000 局护栏 + 确定性/旧档回归，并成一条命令（tools/quality-gate），报告落盘。v0.19 各件已齐，v0.20 只做合并与口径统一。
9. **人生年表 flowchart → 结算道路图升级**：显示走过的节点 + 「差一步」的节点（条件只差一项的叉与结局，给剪影并写明差什么），不展示全图。公开版的分享与重玩钩子，与现有道路图同源。
10. **call/jump 纪律落到代码**：日常 storylet 是 call 型（可复用、返回年循环）；年代推进、婚、育、死是 jump 型单向转移，只许由世界层进程发出。事件模式加 kind 字段，校验器查 jump 型不得进普通池。

不可搬的七条（个别线全量、路线锁、跨周目知识锁、Time Cave 主干、隐形触发器、多视角互锁、靠 skip 刷共通段）与本作既有立场一致，确认不回头，不再议。

## 四、目标架构（三层落到模块）

- **世界层 `src/world/`**：进程是状态的主要写入者，各管自己的文本（进程发声不再散在事件池里——状态线冲突 (a) 类的大头正是进程文本写死他人状态，归位后天然对账）。
  - `state.js`：状态域定义与注册数据（从 registry.js 拆出数据部分；registry 只留校验逻辑）
  - `processes/parents.js`（现有父母进程）、`processes/spouse.js`（相识→相位→离婚/丧偶出口）、`processes/children.js`、`processes/work.js`（职业线 + 工作相位/退休，接 v0.19 的相位设计）、`processes/health.js`（身体 + 死亡曲线，MORTALITY 口径）、`processes/place.js`（居所轨迹）
- **调度层 `src/scheduler.js`**：五层仲裁 + saliency + 温度 derive（吞并 rhythm.js）；锚点表 `src/anchors.js`（按年代）。
- **叙事层 `src/content/`**：事件池按领域重组，结束批次编号：`pool/`（通用）、`lines/`（职业线、关系链）、`rare/`（稀有与组合，收编 synergy 规则为条件层）、`era/`（按年代）、`prologue/`（序章，按年代）。每条一个 storylet 记录，进 registry 统一验。
- **账本 `src/record.js`**：LifeRecord 读写收拢（现散在 engine 里），结构化情节是唯一事实源。
- **呈现层 `src/views/`**：`settlement.js`（特殊结局分层判定：禁止条件先行，再按层判；九槽拼装）、`shadow.js`、`review.js`（年表 flowchart 数据）、`share.js`。
- **engine.js 瘦身为年循环编排**：推进进程 → 调度抽取 → 呈现 → 记账。目标每个文件 <800 行，职责一句话说得清。
- **存档格式不变**：只许加字段、不许改义；旧档可读是护栏，拆分不得动存档语义。

拆分纪律：先搬后改（第一步纯机械拆分，全套回归绿了才动调度语义）；一步一验（每拆一个模块跑一次 quality-gate）；不许借拆分顺手改文案。

## 七、「可公开」判定清单（逐项证据制）

- 玩法：一局全程无阻断（16 局审计为证）；新玩家默认关自动推进；第一局从序章到结算不断线。
- 逻辑：状态线冲突扫描四类归零或逐条有合法说明；职业预设扫描 0；时代错位扫描残余逐条有理由。
- 数值：护栏全过（死亡按年代新带、特殊总率 ≤13%、传说/史诗单体 ≤1%、确定性 200/200、旧档可读、零命中不净增）。
- 内容：c2000 全程无占位文本；四年代均可完整成局；无新增零命中。
- 呈现：手机与桌面各走完一局；分享卡生成成功；年表图可读；「差一步」节点显示正确。
- 方针四条（〇节）：首屏一句话讲清（拿没玩过的人实测，能复述玩法才算过）；两局连玩结果明显不同（组合分布数据 + 审计评审口径）；结算逐槽对账本、无通用判词；结算屏按截图面标准验收（分享卡与年表同屏可截、发出去别人能看懂这一生）。
- 卫生：README 与游戏内说明诚实（不宣传 AI 游戏、Phase 0 定位如实）；分析 KV 已绑或明说未启用；og 图与链接为现行版。
- 留痕：DEVLOG 记 v0.20 一条；本蓝图附销账表；带进公开版的已知欠账写进挂账清单，不装没有。
