# WAVE-EVENTS.md — 浪潮事件组设计（2026-10-31）

> 回答的问题（用户提出）：「能不能让玩家的选择改变本来会发生的大事件的剧情路线？」
>
> **口径（先说结论）：大事件改不了，落到你头上的路线能改。** 恢复高考不会因为某个玩家不考就取消，下岗潮不会因为某个人提前学了手艺就不来——这是红线（不玄幻、不评价政策、大事件只是时代背景）。但同一件大事，以什么面貌、在什么时间、带着什么后果落到某一个具体的人头上，由他早年的选择决定。这正是本产品「选择 + 影子人生」的核心命题在时代尺度上的版本：**浪潮必经，路线自选。**
>
> 素材与纪律：年代锚点取自 content-drafts/SOURCES.md 的 56 条清单与「一局只锚 2–3 条为必经浪潮」的结论；文案纪律以 docs/COPY-AND-AI.md 为准；标记名以代码实测为准（分岔 set 清单见 docs/PM-CONTENT.md §4.8，本文引用的既有标记均已逐个核对存在）；排期口径与 docs/PM-CONTENT.md 的 pack15–20 配额合并（见 §4）。

## 一、机制定义：浪潮事件组

### 1.1 四段结构

一组浪潮 = 同一个时代大事件，在一局里以四段弧线出现：

| 段 | 时点 | 形态 | 作用 |
|---|---|---|---|
| **伏笔** | 本体前 3–5 年（高考组为例外，见 §3.1） | 1–3 条普通事件，进随机池，带抉择并 `set` 标记；也可以是既有事件补 `set` | 玩家在不知道大事将至时做下的选择，成为日后分流的依据 |
| **本体** | 大事件发生的锚点年（单岁） | **必经**。同一组写 3 条本体事件，按标记 `require/forbid` 互斥分流，每名玩家只命中一条；三条的选项、数值后果、后续标记各不相同 | 大事件以与玩家前史相符的面貌落下 |
| **余波** | 本体后 2–5 年 | 1–3 条回响事件，按本体留下的标记分流（优先 `require` 组标记，单线回响可用 `chain`） | 让后果显形：钱、身份、关系的账在这几年结清或翻篇 |
| **影子对照** | 本体当年（呈现层） | 本体事件带一句 `shadowAlt`（建议新字段，见 §1.4）：「另一条路上，同一年……」 | 同种子/影子线里，同一年走的是另一条分支——玩家看见「换一种活法，这件大事会完全不同」 |

结算年表（现有 log 逐年记录）里，四段天然连成一条弧线。建议写 log 时给浪潮事件加可辨认的前缀（如「」），零数据结构改动，年表即可读出弧线；按组聚合的回顾呈现（结算页/分享卡）列为二期，不在本轮范围。

### 1.2 与现有引擎字段的对应

| 设计需要 | 现有字段 | 说明 |
|---|---|---|
| 年代隔离 | `era:"c1955"` 等 | 浪潮组整组带 era（含 c2000 组，见 §3.10 注） |
| 伏笔埋标记 | `choices[].set` | 既有机制；伏笔不设必经，抽不中就走兜底分支 |
| 本体按标记分流 | `require`（字符串或数组）/ `forbid` / `all` / `any` | 三条本体构成**全覆盖划分**：分支一、二各带 require，分支三为兜底（只带 era + wave + 年龄，无其他条件） |
| 本体身份分流（同年双组） | `require` + `forbid` 互斥 | 见 c1965 房改 × 下岗双本体（§3.5） |
| 余波单线回响 | `chain:"<本体事件id>"` | chain 只能指向**一个**事件 id；一组三分支的余波**不要**用 chain 汇合 |
| 余波多线分流 | 本体三分支统一 `set` 一个组标记（如 `xiagang_done`），余波用 `require` 组标记 + 路径标记分流 | 这是组内余波的标准做法 |
| 数值门槛修饰 | `when:{stat,lt\|gt}` | 只作分支内的修饰（如钱够不够），不作主分流条件 |
| 回响加权 | 引擎现行：`require` 命中 ×3、`era` 命中 ×3 | 伏笔与余波靠权重提高到达率，不靠必经 |

### 1.3 「必经」的实现方式：判断与最小引擎改动

**先说清现状为什么做不到必经。** 现有 `pickEvent()` 是「年龄窗内随机池抽一条」：把本体年龄窗收窄到单岁（min=max=锚点岁）、再叠 era 权重 ×3，也只是**提高概率**——同岁还有其他事件竞争，且 step() 的顺序是 分岔 → 瞥视 → 稀有 → 危机 → 事件池，任何一层先触发，本体当年就落空。对「浪潮必经」这个承诺，概率方案不合格：实测口径下只要有 5% 的局漏掉本体，玩家间「同代人共同记忆」的话题基础就塌了。

**结论：需要给引擎加一个小字段，但改动可以压到最小。** 建议方案：

1. **新字段 `wave:"<组id>"`**（如 `wave:"e55_xiagang"`）。带 wave 的事件即本体候选；同组多条靠 require/forbid 互斥，兜底条无条件。
2. **step() 最前面加 `pickWave()` 检查**（在分岔判断之前）：扫描「本岁存在未触发、era 匹配、met() 成立的 wave 事件」→ 直接呈现，并把组 id 记入一个 `waveDone` 集合（或复用 usedEvents 按组判重），保证一组一局只触发一次。代码量约 10–15 行，与现有 fork 先行的结构同构。
3. **配套保险丝：分岔与瞥视改顺延制。** 现行分岔是 `f.age === S.age` 精确触发——若某年被 wave 本体占用，该分岔会**永久丢失**（这是现行代码的真实行为，已核对）。改为 `f.age <= S.age && 未触发` 的到龄顺延：分岔间隔 ≥3 年，本体最多占 1 年，顺延后不会两岔同岁相撞。瞥视（现行 `S.age in GLIMPSE_AGES` 精确触发）同理改顺延，否则瞥视被占岁会静默消失——瞥视是核心卖点，不能丢。改动约 5 行。
4. **锚点避峰纪律（数据侧，能不动引擎就不动）**：本体锚点岁原则上避开分岔岁（25/28/31/33/38/44/52/58）与瞥视岁（30/40/50）。全盘只有两处不可避：非典本体 25 岁（c1978，2003 年就是 25 岁，撞工作分岔）与房改本体 33 岁（c1965）——后者用分流设计化解（§3.5），前者靠顺延保险丝（分岔顺延到 26 岁触发，叙事无碍）。

**验收指标（给集成/模拟）**：每组本体在其年代局 300 局模拟中触发率 = 100%；三分支占比均 > 0；兜底分支占比 < 60%（兜底过高 = 伏笔到达率太低，回调伏笔的年龄窗与权重，而不是动本体）。

### 1.4 影子对照的实现口径（诚实标注）

现有影子线是**按初始路线查表**的文本系统（shadows 的 teaser/stages/cost），不是按玩家标记推演的真模拟——这一点与项目一贯口径一致（影子仍非真推演引擎）。浪潮的影子对照因此也走手写路线：本体事件加一个可选字段 `shadowAlt`（字符串，属于该分支的一句对照，如「另一条路上，同一年，他在海南的工棚里看雨，项目黄了，行李还没拆」）。呈现一期只做一件事：本体卡片下方以影子样式（虚线框）呈现这一句，当年即见对照；结算页按组聚合的对照回顾列为二期。引擎改动仅为渲染层读取该字段，可与 §1.3 的 must 改动打包成一个引擎任务。

### 1.5 分支设计的四条纪律

1. **分支划分必须全覆盖**：任何标记组合（包括伏笔一条没抽中）都要落进某一条本体，兜底分支的剧情因此要认真写——它不是残次品，是「毫无准备地迎上大事」的那种人生，玩家占比可能最高。
2. **分支不分贵贱**：三条分支各有得有失（呼应结局尊严矩阵）。提前有准备的人不许写成赢家叙事，没准备的人不许写成惩罚叙事；差别在**面貌**，不在**报应**。
3. **伏笔的选择当时不许显得「正确」**：伏笔抉择在当年只是普通生活选择（学不学手艺、去不去打听），文案里不许暗示「这一步决定命运」——命运感由玩家在本体年回望时自己产生。
4. **组间允许交叉**：早年浪潮留下的标记可以成为晚年浪潮的分支条件（如 c1955 下海组留下的标记影响下岗组的分支，§3.2 注）。交叉是「人生是一条线」的证据，但每个组最多引用一个外组标记，防条件网失控。
